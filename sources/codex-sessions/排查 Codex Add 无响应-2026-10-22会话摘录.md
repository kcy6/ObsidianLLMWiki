### 助手最终答复

**GNOME** 是一套完整的 Linux 桌面环境，包括文件管理器、设置、窗口管理等。这里的“GNOME 文件选择器”，指 GNOME 提供的打开文件、选择文件夹弹窗；你机器上的这个后端会调用 Nautilus 文件管理器来显示窗口。

### 助手最终答复

**1. 两种后端都会调用 Nautilus 吗？**

不会。针对你当前安装的版本：

| 后端 | 文件选择窗口由谁提供 | 是否依赖 Nautilus |
|---|---|---|
| `xdg-desktop-portal-gnome` | 委托给 Nautilus | 是 |
| `xdg-desktop-portal-gtk` | 自己用 GTK 创建文件选择对话框 | 否 |

GTK 后端虽然也能浏览目录，但它不是启动一个文件管理器，而是直接显示文件选择控件。[GTK 后端源码](https://github.com/flatpak/xdg-desktop-portal-gtk/blob/main/src/filechooser.c)

**2. 为什么 GNOME 后端报错，而 GTK 正常？**

进一步查看你电脑的日志，发现实际出错的是 **Nautilus 崩溃**：

```text
Failed to open service channel Wayland connection
Invalid service client type
Process … (nautilus) … dumped core
Delegated FileChooser call failed: Remote peer disconnected
```

调用过程是：

```text
Codex → Portal → GNOME 后端 → Nautilus 崩溃
                           → 后端报告“对端断开”
```

崩溃栈落在 Wayland 相关函数 `wl_proxy_get_version`。这说明当前 Nautilus 在你的 Niri 环境中，打开文件选择窗口时遇到了 Wayland 交互问题；**仅凭这些日志，还不能确定具体是哪一处兼容性缺陷**。

GTK 后端不经过 Nautilus，因此绕开了这条出错路径。前面我确认了 GTK 服务和接口正常，但是否已经恢复弹窗，还需要以你实际点击 Add 的结果为准。

**3. 为什么多数应用默认使用 GNOME 后端？**

在你这台电脑上，主要是 **Niri 的系统默认配置把 GNOME 排在前面**：

```ini
[preferred]
default=gnome;gtk;
```

应用通常只是向 Portal 请求“选择文件夹”，由 Portal 根据配置决定交给哪个后端。很多应用因此表现出相同的选择，并不是每个应用都自行指定了 GNOME。

`gnome;gtk;` 表示优先选择支持该接口的 GNOME 后端，再考虑 GTK；**不意味着 GNOME 弹窗运行时崩溃后，会自动重试 GTK**。Niri 上游也有关于这一默认配置与文件选择器问题的讨论。[Niri 上游讨论](https://github.com/niri-wm/niri/issues/3765)

这次加上的配置：

```ini
org.freedesktop.impl.portal.FileChooser=gtk;
```

就是明确指定：**文件选择请求交给 GTK，其他接口继续沿用原来的后端配置。**
