本机适合安装虚拟机，**推荐 KVM + QEMU + virt-manager**：KVM 提供硬件加速，QEMU 运行虚拟机，virt-manager 提供图形管理界面。

| 内存 | 约 14 GiB，目前可用 8.4 GiB | 适合同时运行一台中等配置虚拟机 |
| 磁盘 | 根分区剩余约 935 GiB | 空间充足 |
| 软件 | 尚未安装 QEMU、libvirt、virt-manager | 需要安装管理组件 |

**建议安装流程**

1. 安装软件，同时保持 Arch 系统完整更新：

```bash
sudo pacman -Syu --needed qemu-desktop libvirt virt-manager edk2-ovmf dnsmasq swtpm
```

其中 `edk2-ovmf` 提供 UEFI，`swtpm` 提供虚拟 TPM，安装 Windows 11 时会用到。本机已有 nft 后端的 `iptables`，不需要照旧教程额外安装 `iptables-nft`。

2. 启用 libvirt 服务：

```bash
sudo systemctl enable --now libvirtd.service
```

这是 libvirt 官方支持的服务运行方式。[官方说明](https://libvirt.org/daemons.html)

3. 检查虚拟网络：

```bash
sudo virsh -c qemu:///system net-list --all
```

如果存在 `default` 且尚未运行：

```bash
sudo virsh -c qemu:///system net-start default
sudo virsh -c qemu:///system net-autostart default
```

若列表没有 `default`，需先定义默认 NAT 网络。`dnsmasq` 由 libvirt 管理，无需单独开启它的系统服务。

4. 打开管理界面：

```bash
virt-manager --connect qemu:///system
```

选择系统 ISO 创建虚拟机即可。本机正在运行 Polkit 认证代理，可以通过图形弹窗授权。

**虚拟机初始配置建议**

| 用途 | vCPU | 内存 | 虚拟磁盘 |
|---|---:|---:|---:|
| Linux 学习、开发 | 4 | 4 GiB | 40–60 GiB |
| Windows 11 日常使用 | 4 | 6 GiB | 80–120 GiB |

磁盘选择 `qcow2`，通常按实际写入增长；网络先使用默认 NAT。Windows 11 选择 UEFI 和 TPM 2.0，后续安装 VirtIO 驱动。受本机内存限制，暂不建议给单台虚拟机分配 8 GiB 以上。

这套方案利用了本机已经就绪的 KVM，适合作为首选。目前仅完成检查与分析，尚未安装或修改系统。

当前实际状态：

- `qemu-desktop`、`libvirt`、`virt-manager`、`edk2-ovmf`、`dnsmasq`、`swtpm` 均已安装。
- `libvirtd` 已运行，并已设置开机启动。
- KVM 硬件加速检查通过，AMD 嵌套虚拟化已开启（`nested=1`）。
- 用户 `y` 尚未加入 `libvirt` 组；本机已有对应的 Polkit 组授权规则。

**1. 添加用户权限**

以当前普通用户执行：

```bash
sudo usermod -aG libvirt "$(id -un)"
```

然后**注销桌面并重新登录**，让组权限生效。重新打开终端确认：

```bash
id -nG
```

输出应包含 `libvirt`。这一步允许该用户免密码管理系统虚拟机。

**2. 配置默认 NAT 网络**

先查看：

```bash
sudo virsh -c qemu:///system net-list --all
```

如果列表中有 `default`，直接继续；如果没有，先执行：

```bash
sudo virsh -c qemu:///system net-define /etc/libvirt/qemu/networks/default.xml
```

随后设置自动启动：

```bash
sudo virsh -c qemu:///system net-autostart default
```

如果 `default` 的状态是 `inactive`，再启动：

```bash
sudo virsh -c qemu:///system net-start default
```

最后确认：

```bash
sudo virsh -c qemu:///system net-list --all
```

应看到 `default` 为 `active`，自动启动为 `yes`。无需单独启用 `dnsmasq.service`，libvirt 会管理自己的实例。

**3. 打开虚拟机管理器**

用普通用户启动：

```bash
virt-manager --connect qemu:///system
```

点击“新建虚拟机”，选择安装 ISO。建议初始配置：

| 设置 | Linux 虚拟机 | Windows 11 虚拟机 |
|---|---|---|
| CPU | 4 vCPU | 4 vCPU |
| 内存 | 4096 MiB | 6144 MiB |
| 磁盘 | 50 GiB，qcow2 | 100 GiB，qcow2 |
| 网络 | default NAT | default NAT |
| 固件 | UEFI | UEFI，支持 Secure Boot |
| TPM | 无需添加 | 模拟 TPM 2.0 |

Windows 11 在安装前勾选“安装前自定义配置”，确认 UEFI、TPM，并添加文章所述的 VirtIO 驱动 ISO。使用 VirtIO 磁盘时，安装器若找不到磁盘，需要从该 ISO 加载对应驱动。

**文章中，本机需要调整或跳过的部分：**

- 保留已有的 `qemu-desktop`，普通 x86 Windows/Linux 虚拟机无需换成覆盖更多架构的 `qemu-full`。
- 嵌套虚拟化已经开启，跳过修改模块参数和重建 initramfs。
- 使用 NAT，跳过文章的有线网桥配置。
- UEFI 由已安装的固件包提供，普通安装无需手写文章显卡直通部分的旧 `nvram` 路径。
- 显卡直通、Looking Glass、预留大页、CPU 绑核留待明确需要时配置；本机约 14 GiB 内存，先采用上述配置更合适。

有一处需要处理：**你的家目录权限是 `700`，系统 QEMU 进程可能无法读取里面的 ISO。** 建议把镜像复制到 libvirt 目录，不必修改家目录权限。

**1. 准备 ISO**

在宿主机终端执行：

```bash
sudo install -d -m 0755 /var/lib/libvirt/boot

sudo install -m 0644 \
  ~/Downloads/Fedora-KDE-Desktop-Live-44-1.7.x86_64.iso \
  /var/lib/libvirt/boot/Fedora-KDE-Desktop-Live-44-1.7.x86_64.iso
```

这会保留下载目录中的原镜像。

**2. 打开管理器并新建**

```bash
virt-manager --connect qemu:///system
```

点击左上角“创建新虚拟机”，按向导操作：

1. 选择“本地安装介质（ISO 镜像或光盘）”。
2. 点击“浏览”→“浏览本地”，选择：
   ```text
   /var/lib/libvirt/boot/Fedora-KDE-Desktop-Live-44-1.7.x86_64.iso
   ```
3. 系统类型选择 **Fedora Linux 44**；自动识别正确时无需修改。
4. 内存填写 **4096 MiB**，CPU 填写 **4**。
5. 创建 **50 GiB** 虚拟磁盘，使用默认存储池。
6. 名称填写 **fedora44-kde**，网络选择 **default：NAT**。
7. 勾选“安装前自定义配置”，点击“完成”。

这种通过本地介质创建、再在虚拟机内安装系统的流程也见于 [Fedora 官方指南](https://fedoraproject.org/wiki/Get_started_with_Virtual_Machine_Manager_in_Fedora)。

| 项目 | 建议 |
|---|---|

| 固件 | UEFI，使用默认可用固件即可 |
| CPU 模式 | host-passthrough，界面若显示“复制主机 CPU 配置”也可选用 |
| 磁盘总线 | VirtIO |
| 网卡型号 | virtio |
| 显示协议 | SPICE |
| 显卡 | Virtio |
| 3D 加速 | 首次安装先保持关闭 |

Fedora 自带 VirtIO 驱动，无需另挂 Windows 的驱动 ISO。TPM 也无需额外添加。

然后点击“开始安装”。

**4. 在 Fedora 内安装**

1. 启动菜单中选择 **Test this media & start Fedora**，先检查安装介质。
2. 进入 Live 桌面后，打开 **Install to Hard Drive / 安装到硬盘**。
3. 设置语言、时区和用户。
4. 安装目标选择约 **50 GiB 的虚拟磁盘**，使用自动分区即可。这里操作的是虚拟磁盘文件。
5. 完成安装后重启。

如果重启又进入 Live 桌面，关闭虚拟机，在“硬件详情 → SATA CDROM”中弹出 ISO，再启动。也可在“引导选项”中让虚拟硬盘优先启动。

**5. 首次进入已安装的 Fedora**

以下命令在 **Fedora 虚拟机内部**执行：

```bash
sudo dnf upgrade --refresh
sudo dnf install spice-vdagent qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent

```

`spice-vdagent` 用于剪贴板和显示尺寸适配；`qemu-guest-agent` 便于宿主机读取虚拟机信息。后者需要虚拟机硬件中存在名为 `org.qemu.guest_agent.0` 的 VirtIO 信道；如果没有，可关机后通过“添加硬件 → 信道”添加。

以后启动虚拟机，打开 virt-manager 双击 `fedora44-kde` 即可，也可以运行：

```bash
virsh -c qemu:///system start fedora44-kde
```

## 轮次 01a15d05-d0ee-7b10-8860-10c058c8237f

### 用户

怎么和已安装的虚拟机进行文件的传输


### 助手最终答复

如果是刚安装的 **Fedora 虚拟机**，推荐先用 **SFTP**：不需要配置共享目录，可以在宿主机文件管理器里直接拖动文件，双向传输。

**1. 在 Fedora 虚拟机内开启 SSH**

在虚拟机终端执行：

```bash
sudo dnf install openssh-server
sudo systemctl enable --now sshd
```

如果 Fedora 的防火墙正在运行，再执行：

```bash
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

查看用户名和 IP：

```bash
whoami
hostname -I
```

默认 NAT 网络下，IP 通常是 `192.168.122.xxx`。使用这个地址，不要使用网关 `192.168.122.1`。

**2. 在 Arch 宿主机文件管理器中连接**

打开 Dolphin、Thunar 或其他支持 SFTP 的文件管理器，在地址栏输入：

```text
sftp://虚拟机用户名@192.168.122.xxx
```

例如：

```text
sftp://fedora@192.168.122.100
```

首次连接确认主机指纹，输入 **Fedora 虚拟机用户的密码**。连接后，就可以复制、粘贴或拖动文件。

默认 NAT 允许宿主机直接连接虚拟机，**无需桥接，也无需端口转发**。

**3. 也可以使用终端传输**

以下命令均在 **Arch 宿主机**执行，把用户名和 IP 换成实际值：

```bash
# 宿主机 → 虚拟机
scp ~/Downloads/example.zip fedora@192.168.122.100:~/

# 虚拟机 → 宿主机
scp fedora@192.168.122.100:~/example.zip ~/Downloads/

# 传输整个目录
scp -r ~/Documents/myproject fedora@192.168.122.100:~/
```

如果需要长期让两边同时访问同一个目录，可以进一步配置 **Virtiofs 共享文件夹**；偶尔传文件，SFTP 就足够方便。
