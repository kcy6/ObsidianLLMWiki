- "'`~/.config/waybar/config.jsonc`：模块、顺序、显示内容、鼠标操作。JSONC 支持 `//` 注释。
- `~/.config/waybar/style.css`：配色、字体、圆角、边距。使用 GTK CSS，不能直接套用浏览器的 flex、gap、backdrop-filter。
- `~/.config/niri/config.kdl`：开机启动 Waybar，保留一条 `spawn-at-startup "waybar"` 即可。

本目录 `waybar/` 保存一份可修改的初始配置。现在已经复制到用户配置目录并启用。

## 2. 先认识基础版

布局：`工作区 · 窗口标题 | 日期时间 | CPU · RAM · 网络 · 音量 · 电池 · 托盘`。

- 点击工作区：切换。
- 点击时钟：在时间与完整日期间切换；悬停：查看日历。
- 音量上滚/下滚：调整音量；左键：切换静音。
- 网络悬停：查看网络名称和地址。
- 电池不足 30% / 15%：改变文字颜色。

当前使用文字标签，先保证清晰易读，再替换成你喜欢的 Nerd Font 图标。

## 3. 第一次动手：改主题色

编辑 `~/.config/waybar/style.css`，把这一行：

```css
@define-color accent #89b4fa;
```

改成紫色 `#cba6f7` 或绿色 `#a6e3a1`。保存即可自动更新样式。

接着尝试：`font-size: 12px` → `13px`，`border-radius: 14px` → `8px`。
`window#waybar` 控制整个顶栏；`#clock` 控制时钟；`#workspaces button.focused` 控制当前工作区。

顶栏外边距和高度在 JSONC 中调，模块内部留白在 CSS 的 padding 中调。

## 4. 第二次动手：精简信息

在 `modules-right` 数组中删掉 `"cpu"`，CPU 就隐藏了，底部的 CPU 参数块可以留着。
调换数组里的 `"network"` 和 `"wireplumber"`，屏幕上的顺序就会交换。
修改 JSONC 后运行：

```bash
pkill -USR2 -x waybar
```

这会重新加载所有当前用户有权限发送信号的 Waybar 实例。这里预期只有一个常驻实例。

需要前台查看错误时，先在终端停止当前栏，再运行：

```bash
pkill -x waybar
GDK_BACKEND=wayland waybar -c ~/.config/waybar/config.jsonc -s ~/.config/waybar/style.css -l debug
```

前台运行时关闭终端或按 Ctrl+C 会结束该栏。你现有的 niri 快捷键 Mod+F12 可重新启动 Waybar。
本机执行环境设置了 `GDK_BACKEND=x11`，因此调试命令显式选择 Wayland。

## 5. 第三次动手：自己写一个模块

在 JSONC 的最外层对象内新增（注意相邻字段之间加逗号）：

```jsonc
"custom/note": {
  "format": "专注中",
  "tooltip": false
}
```

再把 `"custom/note"` 加进 `modules-left` 数组。在 CSS 末尾追加：

```css
#custom-note {
  color: @accent;
  padding: 0 10px;
}
```

模块名 `custom/note` 对应 CSS ID `#custom-note`。重新加载后即可看到。
后续需要动态内容时再加入 `exec` 和 `interval`，避免一开始就堆脚本。

- 官方配置：https://github.com/Alexays/Waybar/wiki/Configuration

先看仓库 README 的截图，选定一个风格，再阅读配置和依赖。

把预设下载到参考目录，避免直接覆盖正在使用的配置：

```bash
mkdir -p ~/Downloads/waybar-reference
git clone https://github.com/sejjy/mechabar.git ~/Downloads/waybar-reference/mechabar
git clone https://github.com/HANCORE-linux/waybar-themes.git ~/Downloads/waybar-reference/hancore
```

这些命令仅供你挑选预设时运行，本次没有下载仓库或执行其中的脚本。

移植时逐项检查：

1. `hyprland/workspaces` 改为 `niri/workspaces`；`hyprland/window` 改为 `niri/window`，并按 niri 模块文档重新核对参数。
2. `persistent-workspaces` 等选项不要跨合成器照搬；niri 动态工作区的行为不同。
3. 检查每个 `exec`、`on-click`、`include`、CSS `@import` 引用的依赖与路径。
4. 先只移植配色与基础 CSS，再逐个移植模块。整份替换 CSS 时可能需要同步调整模块名称。
5. 透明背景不等于模糊背景；模糊效果取决于合成器能力和配置。
