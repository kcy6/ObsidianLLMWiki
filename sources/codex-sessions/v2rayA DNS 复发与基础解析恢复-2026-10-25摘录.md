**为什么“等待联网”还是没等到？**
本机该服务运行的是 `nm-online -s`，它等待 NetworkManager“完成启动尝试”，允许以未连接状态结束，并不保证 Wi-Fi 已可用。我之前将它描述为等待联网，表述不够准确。

当前最合理的解释是：**v2rayA 在没有外网时初始化，联网后 DNS 转发链路未正常恢复；重启重新建立链路后恢复。** 具体内部故障还不能仅凭这 200 行日志确定。上游也有[相同错误报告](https://github.com/v2rayA/v2rayA/discussions/2076)，但尚无确认的解决结论。

后续应针对两点修复：

- **启动前确认实际存在可用的外网路由**，不能只依赖 `network-online.target`。
- **Wi-Fi 重新连接后重新初始化 v2rayA**，处理开机晚联网、热点变化等情况。

目前测试域名解析、默认连接和显式 SOCKS 连接均已恢复；没有修改你的配置。这次应优先处理启动与网络变化后的恢复机制，而不是继续尝试叠加 v2rayN 或直接更换 DNS。

## 助手

这段记录补上了一个关键证据：**停止 v2rayA 后，系统 DNS 配置是空的。**

你当时的 `/etc/resolv.conf` 只有：

```text
# Generated by NetworkManager
```

没有任何 `nameserver`，随后域名解析也没有成功。因此本次至少存在两个连续问题：

1. **v2rayA 运行时**：日志表明，它向上游 `1.0.0.1:53` 转发 DNS 查询持续失败。
2. **停止 v2rayA 后**：它移除了自身 DNS 配置，但 NetworkManager 没有提供可用的替代 DNS，系统仍然无法解析域名。

这也解释了为什么**仅停掉 v2rayA，再开启另一套代理，不一定能恢复网络**：系统 DNS 已经没有可用服务器。

另外，你重启 v2rayA 后第一次 `getent` 仍失败，说明恢复也不是立即完成的。后来我检查时解析和连接已经正常，只能确认“重新启动后一段时间恢复”，不能认为执行 `restart` 就马上解决了。

**后续需要同时处理两项：**

- 给 Wi-Fi 连接配置可靠的基础 DNS，确保关闭 v2rayA 后系统仍能解析域名。
- 排查 v2rayA 自身的 DNS 上游及联网后恢复机制。

还有一点需要纠正：你这次是在故障后才执行 `systemctl edit`，所以我刚才读取到的配置，**不能证明开机时已经使用了同一份配置**。启动顺序仍是线索，但目前最确定的问题是上述 DNS 故障，不能把根因直接定为“开机启动太早”。

## 助手

建议做两项持久修复：**给 Wi-Fi 配置基础 DNS，并在 Wi-Fi 连上后重新初始化正在运行的 v2rayA。** 这能覆盖这次发现的问题，但不能保证解决所有节点或上游故障。

当前检查发现，`WIFI_PROFILE` 没有手动配置 DNS；等待联网的配置已经存在，无须重复修改。

**1. 为当前 Wi-Fi 保存基础 DNS**

```bash
sudo nmcli connection modify WIFI_PROFILE \
  ipv4.dns "223.5.5.5 119.29.29.29" \
  ipv4.ignore-auto-dns yes
```

这样 NetworkManager 有明确的 DNS 配置，不必完全依赖热点下发。它解决的是基础网络解析，v2rayA 内部的代理 DNS 仍由自身配置控制。

**2. 添加 Wi-Fi 联网后的恢复动作**

复制执行：

```bash
sudo tee /etc/NetworkManager/dispatcher.d/90-v2raya-recover >/dev/null <<'EOF'
#!/bin/sh
# 仅在物理 Wi-Fi 成功连接后，重启正在运行的 v2rayA。
[ "$1" = "WIFI_INTERFACE" ] || exit 0
[ "$2" = "up" ] || exit 0

/usr/bin/systemctl is-active --quiet v2raya.service || exit 0
/usr/bin/logger -t v2raya-recover "Wi-Fi connected; reinitializing v2rayA"
/usr/bin/systemctl --no-block try-restart v2raya.service
EOF

sudo chown root:root /etc/NetworkManager/dispatcher.d/90-v2raya-recover
sudo chmod 755 /etc/NetworkManager/dispatcher.d/90-v2raya-recover
```

这会在开机晚联网或 Wi-Fi 重连时重新初始化代理；**你手动停止 v2rayA 后，它不会擅自启动**。脚本只响应 Wi-Fi `up`，不会因代理修改 DNS 而循环重启。[NetworkManager 官方机制说明](https://networkmanager.dev/docs/api/latest/NetworkManager-dispatcher.html)

**3. 应用并验证**

下面操作可能让当前连接短暂中断：

```bash
sudo nmcli device reapply WIFI_INTERFACE
sudo systemctl restart v2raya
```

然后检查：

```bash
getent ahostsv4 codex-cloud-backend.chatgpt.com
```

能返回 IP，说明当前解析恢复。下次重启后再检查：

```bash
journalctl -b -t v2raya-recover --no-pager
```

这套方案属于针对现有证据的恢复措施；若仍复发，需继续检查 v2rayA 的 DNS 配置及核心错误，不能仅靠自动重启掩盖问题。以上命令需要你在本机输入 sudo 密码执行，我尚未替你应用。
