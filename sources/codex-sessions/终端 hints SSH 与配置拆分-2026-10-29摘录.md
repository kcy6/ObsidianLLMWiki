## 用户

通过示例讲解`kitten hints`使用方式

## 助手

`kitten hints` 的作用是：**给终端屏幕上的网址、路径、整行文字等加上编号，让你通过键盘选取，完成打开、复制或回填。**

它处理的是**已经显示的文字**，与 fzf 搜索文件或历史记录不同。以下按你本机当前配置讲解，不需要再修改配置。

**1．复制屏幕上的网址**

先在 Kitty 中运行：

```zsh
printf '%s\n' \
  'https://www.rust-lang.org/' \
  'https://sw.kovidgoyal.net/kitty/'
```

然后：

1. 按 **`Ctrl+Alt+U`**。
2. 两个网址附近会出现标签，例如 `1`、`2`，实际标签以屏幕为准。
3. 输入目标标签；如果没有立即执行，再按回车。
4. 网址被复制到剪贴板，可用 `Ctrl+Shift+V` 粘贴。

你的配置是：

```conf
map ctrl+alt+u kitten hints --type url --program @
```

其中 `@` 表示复制到剪贴板。若想**直接用浏览器打开**网址，可以使用 Kitty 默认快捷键 **`Ctrl+Shift+E`**，再选择标签。

**2．把屏幕中的路径填入命令行**

先输出两个路径：

```zsh
printf '%s\n' \
  "$HOME/.config/kitty/kitty.conf" \
  "$HOME/.config/starship.toml"
```

接着输入 `nvim `，注意保留末尾空格，**先不要回车**：

```text
nvim ▏
```

按 **`Ctrl+Alt+P`**，选择 `kitty.conf` 对应标签。路径会回填到命令行：

```zsh
nvim /home/example/.config/kitty/kitty.conf
```

检查后按回车，即可编辑。

对应配置：

```conf
map ctrl+alt+p kitten hints --type path --program -
```

这里 `-` 表示**将选择的内容发送回当前终端**。这特别适合选取编译输出、日志中已经出现的文件路径。

**3．复制一整行输出**

比如运行：

```zsh
printf '%s\n' \
  '编译完成：0 个错误' \
  '设备连接：/dev/ttyUSB0'
```

按 **`Ctrl+Alt+L`**，选择某行的标签，就会复制这一整行。

```conf
map ctrl+alt+l kitten hints --type line --program @
```

适合复制错误消息、构建结果或日志，无须用鼠标拖选。复制终端行并不保证保留原始日志中的全部格式。

**4．复制 Git 提交哈希**

在 Git 仓库中运行：

```zsh
git log --oneline -5
```

按 **`Ctrl+Alt+H`**，选择一个哈希标签，将其复制：

```conf
map ctrl+alt+h kitten hints --type hash --program @
```

之后可以输入：

```text
git show ▏
```

再按 `Ctrl+Shift+V` 粘贴哈希，回车查看提交。

**5．从编译报错跳到指定代码行**

这是你后续 C、Rust 开发中值得学习的用法。假设终端显示：

```text
/home/example/Projects/demo/main.c:42: error: ...
```

可以配置一个快捷键，使其选中文件后，在新标签中用 Neovim 打开第 42 行：

```conf
map ctrl+alt+n kitten hints --type linenum --linenum-action tab nvim +{line} {path}
```

**这条尚未加入你的配置**，这里只演示语法：

- `--type linenum`：识别文件路径与行号。
- `--linenum-action tab`：在新的 Kitty 标签页执行。
- `+{line}`：让 Neovim 跳到对应行。
- `{path}`：所选文件路径。

相对路径需要与启动编辑器时的工作目录匹配；绝对路径最容易验证。

你现在先记住这四个已配置的快捷键即可：

| 快捷键 | 选取对象 | 结果 |
|---|---|---|
| `Ctrl+Alt+U` | 网址 | 复制 |
| `Ctrl+Alt+P` | 文件路径 | 回填当前终端 |
| `Ctrl+Alt+H` | 哈希 | 复制 |
| `Ctrl+Alt+L` | 整行文字 | 复制 |

选错模式或不想操作时按 **`Esc`** 退出。目标不在可见区域时，先滚动到它附近，再启动 hints。

## 助手

已重新设计并写入 kitty.conf（原本地文件），统一为 **`Ctrl+Shift+P` 前缀**，避开之前的输入法冲突。

操作方式：先按 `Ctrl+Shift+P`，**全部松开，再按小写字母**。

| 第二键 | 功能 | 处理方式 | 典型场景 |
|---|---|---|---|
| `u` | URL 网址 | 复制到剪贴板 | 分享文档链接 |
| `f` | File 文件路径 | 插入当前命令行 | 输入 `nvim ` 后选择路径 |
| `h` | Hash 提交哈希 | 插入当前命令行 | 输入 `git show ` 后选择哈希 |
| `l` | Line 整行文字 | 复制到剪贴板 | 复制错误信息、日志 |
| `n` | Number 文件行号 | 新标签用 Neovim 打开 | 从 `main.c:42` 跳到代码 |

具体配置：

```conf
# 复制网址
map ctrl+shift+p>u kitten hints --type url --program @

# 插入路径
map ctrl+shift+p>f kitten hints --type path --program -

# 插入哈希
map ctrl+shift+p>h kitten hints --type hash --program -

# 复制整行
map ctrl+shift+p>l kitten hints --type line --program @

# 打开文件并跳到指定行
map ctrl+shift+p>n kitten hints --type linenum --linenum-action tab nvim +{line} {path}
```

**设计上的调整**

- 删除原来的 `Ctrl+Alt+U/L` 自定义绑定，统一入口。
- 哈希由“复制”改为“插入”，更适合 `git show`、`git diff` 等命令，少一次粘贴。
- 整行保持“复制”，避免把日志或整条命令直接回填到 Shell。
- 新增代码行跳转，适合后续 C、Rust 开发。相对路径依赖当前目录，绝对路径最可靠。

**其他功能的取舍**

| 功能 | 建议 |
|---|---|
| 打开网址 | 使用现有默认键 `Ctrl+Shift+E`，不重复添加 |
| 复制路径／哈希的专用键 | 暂不添加，需要分享时可用复制整行或鼠标选取 |
| 单词、IP、正则匹配 | 暂不增加，等有明确需求再配置 |
| 多选路径 | 后续按需加入；目前单选更容易掌握 |
| 文件选择器 | 已有 fzf 的 `Ctrl+T`，不再增加重复入口 |

注意：删除自定义绑定不会禁用 Fcitx5 的 `Ctrl+Alt+P`，它仍然负责输入法预编辑切换。

配置解析检查通过。按 **`Ctrl+Shift+F5`** 重载后体验；这次检查尚未替你实际打开浏览器或编辑文件。

**两者相比，我更推荐第一种分类，但主题文件继续叫 `current-theme.conf`，方便沿用 Kitty 主题工具。**

| 对比 | 第一种 | 第二种 |
|---|---|---|
| 字体 | `fonts.conf` | `fonts.conf` |
| 窗口外观 | `appearance.conf` | `windows.conf` |
| 标签栏 | 独立 `tabs.conf` | 合并到 `windows.conf` |
| 主题颜色 | `theme.conf` | `colors.conf` |
| 特点 | 分类更明确，适合持续扩充 | 文件更少，适合简短配置 |

结合你后续会扩充快捷键、布局和标签栏，建议采用：

```text
~/.config/kitty/
├── kitty.conf           # 入口、Shell、通用行为与布局
├── fonts.conf           # 字体、字号、字符与行间距
├── appearance.conf      # 内边距、透明度、窗口装饰、光标外观
├── tabs.conf            # 标签栏显示条件、样式、标题格式
├── keybindings.conf     # 所有自定义快捷键
└── current-theme.conf   # 主题配色，由主题工具管理
```

关键是明确两个边界：

- **颜色统一归主题文件**：标签栏颜色、光标颜色也放在 `current-theme.conf`，避免主题与其他文件互相覆盖。
- **标签栏结构归 `tabs.conf`**：例如 `tab_bar_style`、`tab_powerline_style`、`tab_bar_min_tabs`；标签页快捷键仍放在 `keybindings.conf`。

主文件可以按这个顺序加载：

```conf
shell zsh
enabled_layouts tall,horizontal

include current-theme.conf
include fonts.conf
include appearance.conf
include tabs.conf
include keybindings.conf
```

文件名本身没有特殊作用，Kitty 只认 `include` 和里面的配置项。**第一种更适合你计划中的扩充；第二种更精简，两者没有性能上的实质区别。** 目前只是分析，没有修改。
