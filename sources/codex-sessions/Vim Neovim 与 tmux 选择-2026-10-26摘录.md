## 助手

**对你准备搭建 Rust、C 和嵌入式开发环境的目标，建议选 Neovim；tmux 暂时不必加入，等有远程开发或保留会话的需求再用。**

**1．Neovim 和 Vim 有什么区别？**

Neovim 从 Vim 分支发展而来，两者都采用“模式编辑”：普通模式用于移动、删除等操作，插入模式用于输入文字。基础按键和编辑习惯高度相通。

| 对比项 | Vim | Neovim |
|---|---|---|
| 定位 | 成熟的通用文本编辑器 | 延续 Vim 编辑方式，更便于扩展开发环境 |
| 配置语言 | 主要使用 Vimscript | 支持 Vimscript，现代配置常用 Lua |
| 基础编辑 | 完整 | 完整，基础操作与 Vim 接近 |
| IDE 功能 | 可以通过插件实现 | 内置 LSP 客户端，便于接入语言服务 |
| 插件兼容 | 不能使用仅面向 Neovim 的插件 | 兼容许多 Vim 插件，也有专属插件 |
| 维护成本 | 基础使用很低；复杂配置仍需维护 | 基础使用很低；完整 IDE 配置仍需维护 |

这里的 **LSP 客户端**是编辑器连接语言服务的接口。Neovim 有这个接口，但你仍需安装 `rust-analyzer`、`clangd` 等服务，才能获得对应语言的补全、跳转与诊断。

选择可以很直接：

- **主要修改系统配置、偶尔编辑脚本**：你现有的 Vim 已经够用。
- **希望长期作为代码主编辑器，逐步加入补全、搜索和调试**：选 Neovim。
- **已经熟悉并拥有稳定的 Vim 配置**：没有必要仅为换工具而迁移。

你目前还没有一套复杂 Vim 配置，直接从 Neovim 开始比较合适。**先学习基础编辑，再添加开发功能**，比一开始装满插件更容易掌握。两者可以同时安装，不需要卸载 Vim。

**2．tmux 是什么？**

**tmux 是终端会话管理工具。** 它在终端内部管理会话、窗口和分屏，并让会话在你断开连接后继续保留。

可以这样区分：

| 工具 | 负责什么 |
|---|---|
| Niri | 管理桌面上的应用窗口 |
| Kitty | 提供终端窗口，也能管理标签和分屏 |
| tmux | 管理终端里的会话、窗口、分屏，以及断开后重新连接 |
| Neovim | 编辑代码 |

例如，你通过 SSH 登录开发板，在 tmux 中打开三个区域：

```text
一个 tmux 会话
├── 编辑代码
├── 编译／查看日志
└── 串口／运行程序
```

网络断开后，只要远端主机没有关机、tmux 会话仍在，其中的程序通常会继续运行。重新 SSH 登录，再连接该会话，就能回到原来的工作现场。

基础操作示例：

```sh
tmux new -s dev    # 创建名为 dev 的会话
tmux ls            # 查看会话
tmux attach -t dev # 重新连接 dev 会话
```

在会话中按 **`Ctrl+B`，松开后按 `D`**，可以离开会话而不结束它。

需要注意：**tmux 保留会话不等于关机恢复**。机器重启后，原来的进程不会自动保留，它也不能替代程序自身的持久运行机制。

对你当前的本地开发，**Niri + Kitty + Neovim 已经足够**。以后经常 SSH 到开发板、服务器，或者希望关闭终端后编译任务仍能继续运行时，再加入 tmux，会更容易体会它的价值。
