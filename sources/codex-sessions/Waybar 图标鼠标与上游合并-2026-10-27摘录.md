## 用户

左上角工作区以数字提示，预览图中是以图标，怎么改善


## 助手

现在显示数字，是因为之前为验证 niri 兼容性，使用了：

```jsonc
"niri/workspaces": {
  "format": "{index}"
},
```

把它改成**按工作区状态显示图标**即可。

打开 config.jsonc（原本地文件），将已有的 `"niri/workspaces"` 块替换为：

```jsonc
"niri/workspaces": {
  "format": "{icon}",
  "format-icons": {
    "focused": "",
    "active": "",
    "default": ""
  }
},
```

这是沿用 Mechabar 预设的图标，并补上 niri 的焦点状态：

| 配置 | 作用 |
|---|---|
| `"format": "{icon}"` | 显示图标，取代编号 |
| `"focused"` | 当前获得焦点的工作区 |
| `"active"` | 在其显示器上可见的工作区 |
| `"default"` | 其他工作区 |

保存后重载：

```bash
pkill -USR2 -x waybar
```

主题已经有工作区选中时放大、变色的 CSS，因此先不需要修改样式。

如果更喜欢简单清晰的圆点，也可以换成：

```jsonc
"niri/workspaces": {
  "format": "{icon}",
  "format-icons": {
    "focused": "●",
    "active": "●",
    "default": "○"
  }
},
```

**先确认图标显示正常，再调整大小和间距。** 如果出现方框，通常是字体缺少对应字形；第二组普通圆点更适合排查这类问题。

## 用户

为什么鼠标点击左上角切换工作区后鼠标不会保持原位置而是每次都跳动到了屏幕左侧中央


## 助手

原因找到了：你的 niri 配置启用了 **`warp-mouse-to-focus`，焦点切换时自动移动鼠标**。

在 config.kdl 第 67 行（原本地文件）：

```kdl
warp-mouse-to-focus
```

点击 Waybar 切换工作区后，niri 会聚焦那个工作区中的窗口，并把鼠标移动到该窗口内。默认会分别调整横、纵坐标，因此可能表现为鼠标横向位置基本不变，却跳到了屏幕左侧中央。[niri 官方说明](https://niri-wm.github.io/niri/Configuration%3A-Input.html#warp-mouse-to-focus)

要保持鼠标原位，把这一行注释掉：

```kdl
// warp-mouse-to-focus
```

保存后 niri 通常会自动加载配置，直接点击工作区验证即可，**不需要重启 Waybar**。

旁边这行可以保留：

```kdl
focus-follows-mouse max-scroll-amount="0%"
```

两者方向不同：

| 设置 | 行为 |
|---|---|
| `warp-mouse-to-focus` | 焦点变化 → 鼠标自动移动 |
| `focus-follows-mouse` | 你移动鼠标 → 焦点跟随鼠标 |

注意，关闭后，**使用键盘切换窗口时，鼠标也会保持原位**。

## 用户

/home/example/.config/waybar做的所有修改后续如果我通过git更新了上游仓库是不是都会消失，有什么好的管理方式吗


## 助手

**正常执行 `git pull`，不会直接把你的修改全部覆盖。** 但目前你的修改还没有提交，建议先建立自己的分支并保存版本，再更新上游。

我检查了当前状态：

```text
main 跟踪 origin/main
config.jsonc 已修改，未提交
style.css    已修改，未提交
```

**1．更新时实际会发生什么？**

| 操作 | 对本地修改的影响 |
|---|---|
| `git fetch origin` | 只下载上游更新，不改变你的配置 |
| `git pull` | 尝试整合更新；若会覆盖未提交修改，通常中止并提示 |
| 合并时发生冲突 | 需要人工决定保留哪些内容 |
| `git reset --hard origin/main` | 会丢弃已跟踪文件的本地修改，恢复成上游版本 |

所以，**不要用 `reset --hard` 解决更新冲突**。

**2．适合你现在的方式：个人分支＋提交＋合并上游**

不必马上搭建复杂的 dotfiles 系统。先在当前仓库创建一个自己的分支：

```bash
cd ~/.config/waybar
git switch -c personal/niri
```

目前尚未提交的修改会一起带到新分支。检查并保存：

```bash
git diff
git add config.jsonc style.css
git commit -m "适配 niri 并自定义顶栏样式"
```

提交相当于创建一个**有说明、可比较、可恢复的存档**，不会上传到 GitHub。

以后每完成一项效果，保存一次，例如：

```bash
git add config.jsonc style.css
git commit -m "调整顶栏圆角和工作区图标"
```

**3．以后怎么更新上游？**

先确保当前修改都已提交：

```bash
git status
```

看到工作区干净后，再执行：

```bash
git fetch origin
git merge origin/main
```

这两步分别表示：

1. 下载 Mechabar 的更新。
2. 把更新合并进你的个人分支，保留自己的提交。

如果双方修改了同一段配置，可能发生冲突。解决前，Waybar 的自动重载可能读到冲突标记，所以**最好先在仓库外备份当前可用配置**。不想继续这次合并，可以运行：

```bash
git merge --abort
```

这能撤销正在进行的合并，前提是你合并前已经把工作区整理干净。

**4．让后续更新更省心：减少对上游文件的修改**

等你熟悉配置后，可以逐步这样拆分：

```text
~/.config/waybar/
├── config.jsonc          上游主配置，保留少量必要修改
├── style.css            上游样式，末尾引入个人样式
└── personal/
    ├── niri.jsonc        自己的 niri 模块参数
    └── overrides.css    自己的圆角、颜色、间距
```

在 `style.css` **最后**加入：

```css
@import "personal/overrides.css";
```

把个人样式集中放进 `overrides.css`，同等优先级下可覆盖前面的规则。这样上游改动样式时，通常更容易合并。

JSONC 的 `include` **不能照搬 CSS“后面覆盖前面”的思路**：Waybar 配置重复时优先使用先定义的值。因此模块数组、包含顺序仍需认真管理，拆文件不等于完全免冲突。

对你目前的学习阶段，先完成**创建个人分支、提交当前两个文件**就足够了。之后再整理个人配置目录；远程备份则可以使用自己的 GitHub 私有仓库，避免仅有本机一份存档。
