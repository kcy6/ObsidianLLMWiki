## 助手

三个路径都正确，只有 `dirname` 实际输出的 `dest_dir` 通常不带末尾 `/`，不影响你对目录的理解。备份流程先暂停，我们复习 Kitty，并围绕你的两类终端来配置。

你想要的行为可以对应为：

| 用途 | 启动方式 | app-id | 窗口行为 |
|---|---|---|---|
| 长期使用的终端 | `kitty --single-instance` | `kitty` | 平铺 |
| 临时终端 | `kitty --single-instance --class quickterminal` | `quickterminal` | 浮动 |

之前学过的关键是：**启动参数指定标识，Niri 根据标识应用窗口规则。** `--single-instance` 用于复用 Kitty 进程，不表示复用已有窗口，也不会让窗口自动隐藏或关闭。

快捷键可以沿用项目中的安排：

```kdl
// 长期使用：平铺终端
Mod+T {
    spawn "kitty" "--single-instance";
}

// 临时使用：浮动终端
Mod+Slash {
    spawn "kitty" "--single-instance" "--class" "quickterminal";
}
```

对应窗口规则：

```kdl
window-rule {
    match app-id="^kitty$"
    open-floating false
}

window-rule {
    match app-id="^quickterminal$"
    open-floating true
    default-column-width { proportion 0.7; }
    default-window-height { proportion 0.6; }
}
```

`^` 和 `$` 表示精确匹配整个 app-id。这里临时终端默认占约 70% 宽、60% 高；“临时”只是用途，每次触发仍会新开窗口。

先明确你的交互需求，再完成配置：**再次按 `Mod+/` 时，你希望再开一个临时终端，还是让同一个临时终端显示／隐藏？** 后者需要增加切换逻辑，单靠上面的 `spawn` 无法实现。

## 用户

怎么给该浮动终端配置较高的透明度


## 助手

在匹配 `quickterminal` 的窗口规则中加入 `opacity`：

```kdl
window-rule {
    match app-id="^quickterminal$"
    open-floating true
    opacity 0.75
    default-column-width { proportion 0.7; }
    default-window-height { proportion 0.6; }
}
```

**数值越低，越透明**：`1.0` 完全不透明，`0.75` 表示约 75% 不透明度。把这条规则放在全局透明度规则之后。

不过，Niri 的 `opacity` 会让**文字和背景一起透明**。如果你希望文字保持清晰、只有背景透明，应给这个 Kitty 单独传参数：

```kdl
Mod+Slash {
    spawn "kitty" "--single-instance"
        "--class" "quickterminal"
        "-o" "background_opacity=0.75";
}
```

此时窗口规则使用 `opacity 1.0`，避免两层透明度叠加。普通终端的背景透明度不会因此改变。

你想要的是哪种效果：**整个窗口一起透明，还是只让背景透明、文字保持清晰？**

## 用户

最高透明度是多少，为什么即便我跳到0.5感觉也不明显


## 助手

如果你调的是 `opacity` 或 `background_opacity`，它们表示**不透明度**，数值越低越透明：

| 值 | 效果 |
|---|---|
| `1.0` | 完全不透明 |
| `0.5` | 半透明 |
| `0.0` | 完全透明 |

区别是：Niri 的 `opacity 0.0` 会连文字一起隐藏；Kitty 的 `background_opacity=0.0` 只让背景完全透明，文字仍显示。

你调到 `0.5` 仍感觉不明显，可能有两个原因：

- **背景模糊与暗化影响观感。** 这个项目配置了 blur/xray，透出的背景可能仍像一块深色底，看不清壁纸细节。
- **配置没有作用到目标窗口。** Kitty 启动参数中的 `-o` 应通过快捷键重新打开窗口验证；Niri 规则则要匹配实际的 app-id。普通 Kitty 配置不会自动等同于 `quickterminal` 的配置。

先做一次容易判断的对照：保持 Niri 的 `opacity 1.0`，给临时 Kitty 设置：

```kdl
"-o" "background_opacity=0.0"
```

重新打开临时终端，观察**空白背景区域**是否明显透出壁纸，文字应该保持清晰。

你刚才修改的是 **Niri 的 `opacity`**，还是 **Kitty 的 `background_opacity`**？把对应配置贴出来，我们下一步就能判断是模糊效果还是配置未生效。

## 助手

它们**不冲突，而是叠加生效**，因为控制的是不同层：

| 配置 | 作用 |
|---|---|
| Kitty 的 `background_opacity` | 只调整终端背景，文字保持清晰 |
| Niri 的 `opacity` | 调整整个窗口，包括文字和背景 |

比如：

```text
Kitty：background_opacity 0.5
Niri：opacity 0.8
```

背景最终的不透明度约为 `0.5 × 0.8 = 0.4`，文字则约为 `0.8`。实际观感还取决于后方画面。

你当前 Kitty 是 `0.95`，Niri 最终被后面的全局规则设成 `0.99`，所以背景约为 `0.9405`，看起来仍然很实。

对于你想要的“清晰文字＋透明浮动终端”，建议这样分工：

window-rule {
    match app-id="^quickterminal$"

## 用户

如果我希望每次打开浮动终端都在屏幕右下角呢


## 助手

在临时终端的 `window-rule` 中添加 `default-floating-position`：

```kdl
// 放在全局窗口规则之后
window-rule {
    match app-id="^quickterminal$"
    open-floating true
    opacity 1.0

    default-column-width { proportion 0.7; }
    default-window-height { proportion 0.6; }

    default-floating-position x=20 y=20 relative-to="bottom-right"
}
```

`relative-to="bottom-right"` 以右下角为基准，`x=20 y=20` 表示距离右边、下边各留 20 个逻辑像素。

这是**新窗口的初始位置**，打开后仍可以拖动，不会被固定在那里。它与透明度配置互不影响。

## 助手

这四个问题可以串起来理解：**Niri 管窗口的大小和位置，Kitty 管终端显示，Zsh 管命令交互。**

**1. 两个尺寸配置的数值含义**

```kdl
default-column-width { proportion 0.7; }
default-window-height { proportion 0.6; }
```

| 配置 | 控制什么 | 当前数值 |
|---|---|---|
| `default-column-width` | 初始宽度，浮动窗口也适用 | 约占屏幕可用宽度的 70% |
| `default-window-height` | 初始高度 | 约占屏幕可用高度的 60% |

`proportion` 是比例，不是像素，实际尺寸还会考虑间距等布局因素。也可以使用固定的**逻辑像素**：

```kdl
default-column-width { fixed 900; }
default-window-height { fixed 550; }
```

逻辑像素会受显示器缩放影响，不一定等于物理像素。这些设置决定初始尺寸，打开后仍能手动调整。[Niri 官方窗口规则说明](https://niri-wm.github.io/niri/Configuration:-Window-Rules.html#default-column-width)

**2. `--class` 和 `-o` 分别做什么**

```bash
kitty --class quickterminal -o background_opacity=0.6
```

- `--class quickterminal`：在 Wayland 下把窗口的 **app-id** 设置为 `quickterminal`，供 Niri 匹配。它本身不负责浮动。
- `-o background_opacity=0.6`：覆盖这次启动使用的 Kitty 配置项，不修改 `kitty.conf`。`-o` 是 `--override` 的缩写，可以重复使用。

例如：

```bash
kitty --class quickterminal \
    -o background_opacity=0.6 \
    -o font_size=14
```

[Niri 的启动参数中，每个选项与值分别写成字符串即可；参数含义见 Kitty 官方说明。](https://sw.kovidgoyal.net/kitty/invocation/)

**3. 已有常驻终端，再开浮动终端，会复用进程吗**

如果两次都带 `--single-instance`，使用相同实例组，且第一个实例仍在运行，新的启动请求会交给已有 Kitty 进程，由它创建新窗口：

```text
一个 Kitty 主进程
├── 常驻窗口 → Zsh 进程 A
└── 浮动窗口 → Zsh 进程 B
```

**窗口独立，Shell 独立，Kitty 主进程复用。** 不同的 `--class` 仍可区分窗口，不会因此自动分成两个进程组。

如果第一个终端启动时没带 `--single-instance`，后面的调用不能直接把它当作可复用实例。还可以用 `--instance-group` 主动划分组。[Kitty 单实例说明](https://sw.kovidgoyal.net/kitty/invocation/#cmdoption-kitty-single-instance)

**4. 后开的终端会继承什么，会加速什么**

| 项目 | 实际效果 |
|---|---|
| Kitty 主进程与 GPU 字形缓存 | 可以复用，减少资源开销并加快窗口启动 |
| 已有窗口的文字、滚动记录、正在运行的命令 | 不会复制 |
| 原 Zsh 中临时定义的变量、函数、别名 | 不会自动复制 |
| 原 Zsh 当前目录 | 单靠 `--single-instance` 不会自动跟随 |
| Zsh 与插件初始化 | 每个新 Shell 仍需执行 |
| 命令历史 | 是否及时共享取决于 Zsh 历史配置 |

新交互式 Zsh 通常仍会读取 `.zshrc`，执行插件初始化。系统文件缓存可能让后续读取更快，但 **`--single-instance` 不会复用已经初始化好的 Zsh 或插件状态**。[Zsh 启动文件说明](https://zsh.sourceforge.io/Doc/Release/Files.html)

所以，“窗口很快出现”和“提示符很快准备好”是两个性能问题：前者可能受益于 Kitty 进程复用，后者需要分析 Zsh 配置。
