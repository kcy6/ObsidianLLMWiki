## 1. 解释器与基本写法

```bash
#!/usr/bin/env bash
```

直接启动可执行脚本时，首行选择解释器。文件扩展名不决定语言。`bash script` 显式使用 Bash；不能随意改为 `sh script`，因为数组、`[[ ]]`、进程替换等并非 POSIX sh 通用语法。

- 命令参数以空白分隔，不使用函数调用式逗号和括号。
- 换行或英文 `;` 分隔命令。
- 中文 `；` 不是命令分隔符。
- `#` 在注释位置开始注释；参数展开中的 `#` 有其他用途。
- `cp`、`dirname`、`find` 是命令；变量、循环、条件负责组织它们。

```bash
name="niri"                 # = 两侧不能有空格
echo "$name"
echo "${name}_config"       # 花括号明确变量名边界
```

## 2. 引号、展开与转义

### 2.1 单引号与双引号

```bash
name="niri"
printf '%s\n' '$name'       # 字面文本 $name
printf '%s\n' "$name"       # niri
```

引号一般是 Shell 语法，不是保存到变量里的字符。双引号允许变量、命令和算术展开，并保护普通参数边界；单引号保留原文。

```bash
path="/home/example/My Files/config.kdl"
dirname -- "$path"
```

普通命令参数中的未引用展开可能经历：**变量展开 → 分词 → 文件名通配展开**。

```bash
name="My Config"
show_args $name "niri"      # 3 个参数：My、Config、niri
show_args "$name" "niri"    # 2 个参数：My Config、niri
```

这个规则不能不加区别地套到赋值、`[[ ]]` 等语法环境上。

### 2.2 通配展开与 --

假设目录只有 a.kdl、b.kdl、notes.txt：

```bash
pattern="*.kdl notes.txt"
show_args $pattern          # 3 个文件名参数
show_args "$pattern"        # 1 个字面参数：*.kdl notes.txt
```

引号防止分词、通配展开；`--` 解决另一个问题：结束命令选项解析。

```bash
file="-n"
cat "$file"                # cat 会把 -n 当作选项
cat -- "$file"             # 读取名为 -n 的文件
cat -n -- "-notes.txt"      # 显示行号，读取名为 -notes.txt 的文件
```

许多命令支持 `--`，并非所有命令都支持。

### 2.3 续行、换行字符与输出

```bash
cp -a -- \
    "$src_file" \
    "$dest_file"
```

反斜杠必须紧接换行；后面不能再放空格。反斜杠加换行会被移除，将两行接起来。

```bash
text=$'kitty\nwaybar'        # ANSI-C 引号，内容包含真实换行
text='kitty\nwaybar'         # 普通单引号，内容包含字面的反斜杠和 n
```

| 写法 | 行为 |
|---|---|
| `printf '%s\n' "$text"` | 原样输出参数，末尾换行 |
| `printf '%b\n' "$text"` | 解释参数中的反斜杠转义 |
| `echo -e "$text"` | 解释转义，但不同环境行为可能有差异 |

优先使用固定格式 `printf '%s\n' "$text"`。不要直接用 `printf "$text"`，否则内容中的 `%` 等会被当作格式。`printf '<%s>\n' "$text"` 中的尖括号会原样输出，不能漏写。

## 3. 命令替换、算术展开与字符串处理

### 3.1 三类常见括号

| 写法 | 用途 |
|---|---|
| `${name}` | 变量或参数展开 |
| `$(dirname -- "$path")` | 执行命令，捕获标准输出 |
| `$((count + 1))` | 算术展开，产生数值文本 |
| `((count += 1))` | 算术命令，执行运算并返回状态 |
| `( commands )` | 子 Shell 环境，见第 11 节 |

```bash
dest_dir="$(dirname -- "$dest_file")"
```

命令替换移除输出末尾的换行符，不捕获标准错误，除非主动重定向。它捕获文本，不是 return 的数字。

反引号也是旧式命令替换：不要写成 `mkdir ... ` 后再用反引号包住 `|| return 1`。失败处理应直接写为代码。

### 3.2 字符串与路径展开

```bash
file="./.config/My App/settings.ini"
rel_path="${file#./}"         # .config/My App/settings.ini
```

`${var#模式}` 删除开头匹配的最短前缀，不匹配则原样保留；不会按空格截断。路径拼接也不会自动缩写为 `~`：

```bash
# 假设 HOME 原本为 /home/example，rel_path=.config/kitty/kitty.conf：
# "$HOME/$rel_path" → /home/example/.config/kitty/kitty.conf
```

其他常用形式：

```bash
input="abcdef"
printf '%s\n' "${input:2}"       # cdef
printf '%s\n' "${input:2:3}"     # cde，第三项是长度，不是结束下标
printf '%s\n' "${target:-默认值}" # 未设置或为空则使用默认值，不修改变量
```

`${target:=默认值}` 还会赋值，本轮仅作区别提示。删除字面的 `~/` 可写 `${input#\~/}`；`${input:2}` 只是固定截取，需要调用者先确认前缀。

```bash
NORMALIZED_PATH="${canonical_path#"$canonical_home"/}"
```

这里删除“家目录路径加斜杠”的前缀；应先验证路径确实属于家目录，不能把字符串截取当作完整路径安全检查。

## 4. 函数、位置参数与两条返回通道

```bash
show_path() {
    local base="$1"
    local file="$2"
    printf '%s/%s\n' "$base" "$file"
}
show_path "/tmp/templates" "config.ini"
```

定义函数不会立即执行；调用不写调用括号，也不写逗号。

| 语法 | 含义 |
|---|---|
| `$1`、`$2` | 当前函数或脚本的第一个、第二个参数 |
| `$#` | 参数数量 |
| `"$@"` | 所有参数，分别保持边界 |
| `local name` | 函数局部变量 |
| `return N` | 结束当前函数，设置状态 N |
| `exit N` | 结束当前 Shell 进程；脚本中通常结束脚本 |
| `$?` | 上一条命令的退出状态 |

`$0` 不是函数的第一个参数。函数内参数与外层脚本参数分开理解。没有显式 return 时，函数状态取最后执行命令的状态。

### 文本输出与退出状态必须分开

```bash
get_helper() {
    printf '%s\n' "yay"
    return 1
}
helper=$(get_helper)
status=$?
printf 'helper=%s，status=%s\n' "$helper" "$status"
# helper=yay，status=1
```

- stdout 传递文本，`$(...)` 可以捕获。
- return 传递成功失败，不输出文本。
- 有文本不等于成功；没有文本也不等于失败。
- `$?` 要立即保存，后续命令会覆盖它。

```bash
false
echo "$?"    # 1
echo "$?"    # 0，上一条 echo 成功
```

### 命令状态与算术值

| 语境 | 0 | 非零 |
|---|---|---|
| 命令退出状态 | 成功，if 进入 then | 失败，if 进入 else |
| 算术表达式值 | 假 | 真 |

`((...))` 会做转换：表达式值为 0 时返回状态 1；非零时返回状态 0。

```bash
((5)); echo "$?"   # 0
((0)); echo "$?"   # 1
```

## 5. 条件与逻辑连接

```bash
if 条件命令; then
    成功分支
elif 另一个条件命令; then
    另一个成功分支
else
    失败分支
fi
```

if 根据命令的退出状态判断。Bash 条件结构 `[[ ... ]]` 的内侧需要空格；取反可写 `! [[ ... ]]` 或 `[[ ! ... ]]`，不能写 `![[ ... ]]`。

### 常用判断

| 表达式 | 含义 |
|---|---|
| `[[ "$a" == "$b" ]]` | 字符串相等 |
| `[[ "$a" != "$b" ]]` | 字符串不等 |
| `[[ -z "$value" ]]` | 空字符串 |
| `[[ -n "$value" ]]` | 非空字符串 |
| `[[ "$n" -eq 2 ]]` | 整数相等 |
| `-ne / -gt / -lt / -ge / -le` | 整数不等、大于、小于、大于等于、小于等于 |
| `[[ -e "$path" ]]` | 路径存在，悬空符号链接不满足 |
| `[[ -f "$path" ]]` | 普通文件；通常跟随符号链接判断目标 |
| `[[ -d "$path" ]]` | 目录 |
| `[[ -L "$path" ]]` | 符号链接，包括悬空链接 |
| `-r / -w / -x` | 当前用户可读、可写、可执行；目录的 x 表示可搜索遍历 |

```bash
[[ "02" == "2" ]]   # 文本不同，失败
[[ "02" -eq "2" ]]  # 此例整数值相同，成功
```

算术语境中前导 0 可能表示八进制，不能把任意零开头字符串都当十进制。

### &&、||、! 与分组

```bash
command_a && command_b  # A 成功才执行 B
command_a || command_b  # A 失败才执行 B
cd -- "$dir" || return 1

command_a || {
    printf '%s\n' "失败" >&2
    return 1
}
```

短路执行：前者的状态已决定是否继续时，后面的命令不会运行。`A && B || C` 不是完整 if/else：A 成功、B 失败时，C 仍会运行。命令列表中的 &&、|| 同优先级，左结合。

`command || true` 容忍失败，不会修复失败的操作。

### [ ] 与 [[ ]]

`[` 是 test 命令的一种形式，POSIX Shell 支持；`[[ ]]` 是 Bash 等 Shell 的条件语法。两者都要求必要空白。

```bash
[ -n "$path" ] && [ -f "$path" ]
[[ -n "$path" && -f "$path" ]]
```

`[ ]` 中可移植字符串相等写 `=`，不支持 Bash 这种正则/通配判断；变量尤其需要引用。

## 6. 通配模式、正则与 case

### 通配模式

```bash
[[ "$name" == *.kdl ]]
[[ "$path" == "$prefix/"* ]]
[[ "$value" == \#* ]]
```

未被引用的 `*` 表示任意长度内容；引号包住的部分按字面匹配。

```bash
[[ "$path" == "$prefix/"* ]]  # 星号参与模式匹配
[[ "$path" == "$prefix/*" ]]  # 星号是字面字符
```

加斜杠避免 `.config/niri` 误匹配 `.config/niri-backup/a`。`[[ ]]` 中模式匹配不是在列举磁盘文件。

### 正则

```bash
[[ "$confirm" =~ ^[Yy]$ ]]  # 恰好一个 Y 或 y
[[ "$confirm" =~ [Yy] ]]    # 包含 Y/y 即可，yes 也匹配
[[ "$name" =~ \.kdl$ ]]     # 末尾为字面 .kdl
```

`^` 开头，`$` 结尾，`[Yy]` 字符集合。正则的 `.` 表示任意单字符，`\.` 是字面点；正则 `*` 修饰前面的部分，与通配模式中的含义不同。不要随意把整段正则加引号，否则可能变成字面匹配。

### case

```bash
case "${1:-}" in
    init)
        printf '%s\n' "初始化"
        ;;
    update)
        printf '%s\n' "更新"
        ;;
    *)
        printf '%s\n' "用法错误" >&2
        exit 1
        ;;
esac
```

case 按模式选择分支，`;;` 结束分支，`*)` 通常兜底，`esac` 结束结构。

## 7. 数组与参数边界

```bash
items=("hello world" "niri" "waybar")
items+=("mako")
printf '%s\n' "${items[0]}"    # hello world
printf '%s\n' "${#items[@]}"   # 4
```

数组下标从 0 开始；函数参数从 `$1` 开始。

| 展开 | 双引号内效果 |
|---|---|
| `"${items[@]}"` | 每个元素分别作为一个参数 |
| `"${items[*]}"` | 合成一个参数，用 IFS 的首字符连接 |

```bash
show() {
    printf '数量=%s\n' "$#"
    printf '第一个=<%s>\n' "$1"
}
items=("My Files" "niri")
show "${items[@]}"
# 数量=2
# 第一个=<My Files>
```

`show "${items[*]}"` 默认 IFS 下收到一个参数 `My Files niri`。函数只输出它实际写出的东西；如果函数体仅 `echo "$#"`，不会额外输出元素。

## 8. 循环、算术与控制范围

### for 与逐轮执行

```bash
for item in x y; do
    printf '开始：%s\n' "$item"
    printf '完成：%s\n' "$item"
done
```

顺序是开始 x、完成 x、开始 y、完成 y。每轮执行完整循环体，再取下一个元素，不是先跑完所有第一条语句。

| 语句 | 作用 |
|---|---|
| continue | 跳过本轮剩余语句，进入下一轮 |
| break | 退出当前循环，不撤销此前操作 |
| return | 退出当前函数；调用者默认仍可继续 |
| exit | 退出当前 Shell 进程 |

```bash
for item in x y z; do
    printf '开始：%s\n' "$item"
    if [[ "$item" == "y" ]]; then
        continue
    fi
    printf '完成：%s\n' "$item"
done
echo "结束"
```

输出：开始 x、完成 x、开始 y、开始 z、完成 z、结束。若将 continue 改为 break，输出到开始 y 后就跳到结束。

### 算术与递增

```bash
next=$((count + 1))   # 产生数值并赋给 next
((count += 1))       # 修改 count
```

`failed++` 单独写不是算术命令，会被当作命令名；应写 `((failed++))` 或 `((failed+=1))`。

| 从 count=0 开始 | 表达式值 | 运算后 count | 命令状态 |
|---|---:|---:|---:|
| `((count++))` | 0，旧值 | 1 | 1 |
| `((++count))` | 1，新值 | 1 | 0 |
| `((count+=1))` | 1，新值 | 1 | 0 |

任何算术命令都可能因表达式值为 0 返回状态 1；不能把前置递增当成所有场景下都不会触发 set -e 的保证。

```bash
for (( i=2; i<${#backups[@]}; i++ )); do
    printf '%s\n' "${backups[i]}"
done
```

三段依次是初始化、继续条件、每轮结束操作。从下标 2 开始意味着跳过前两项。

## 9. 重定向、管道与多行输入

### 标准通道

| 编号 | 名称 |
|---|---|
| 0 | stdin 标准输入 |
| 1 | stdout 标准输出 |
| 2 | stderr 标准错误 |

```bash
command > result.log       # 覆盖标准输出
command >> result.log      # 追加标准输出
command < input.txt        # 从文件读取标准输入
command 2> errors.log      # 标准错误写文件
printf '%s\n' "失败" >&2    # 写标准错误，不是隐藏
command >/dev/null 2>&1     # 丢弃正常输出与错误输出
```

重定向从左到右处理，`2>&1` 复制 stdout 当时的连接，不是永久跟随。

| 写法 | 初始 stdout/stderr 都连终端时的结果 |
|---|---|
| `command >/dev/null 2>&1` | 二者都丢弃 |
| `command 2>&1 >/dev/null` | stdout 丢弃，stderr 仍去终端 |
| `command >result.log 2>&1` | 二者都写 result.log |

外层还有管道或重定向时，按实际初始连接分析。隐藏输出不改变命令本身的成功失败。

### 管道

```bash
locale -a | grep -iq "zh_CN.utf8"
```

普通 `|` 连接左侧 stdout 和右侧 stdin，不自动转交 stderr。`grep -i` 忽略大小写，`-q` 不输出匹配文本，通过状态报告找到与否。管道状态见第 12 节。

### here-string 与 read 数组

```bash
relative_dir=".config/niri/scripts"
IFS='/' read -r -a path_parts <<< "$relative_dir"
# path_parts=(".config" "niri" "scripts")
```

`<<<` 将字符串作为 stdin 并补换行；`IFS='/'` 为本次 read 设置分隔符，`-a` 读入数组，`-r` 保留反斜杠。

### here-document

```bash
name="niri"
cat << EOF
组件：$name
EOF
# 输出 组件：niri

cat << 'EOF'
组件：$name
EOF
# 输出字面 组件：$name
```

引用结束标记会禁止正文的变量、命令、算术展开；结束行仍写 EOF，不写引号。普通 `<<` 的结束标记不能随意缩进。标记名称可自选。

源码里的 `sudo tee "$POL_DIR/policies.json" > /dev/null << 'EOF'`：tee 读取多行输入写文件，sudo 给 tee 写权限，重定向隐藏 tee 同时复制到 stdout 的那一份。这里只说明语法，不执行系统文件写入。

## 10. 读取文件、进程替换与路径分隔

### mapfile：整份读入数组

```bash
mapfile -t items < "$file"
```

一行一个元素，`-t` 去掉分隔符，默认是行末换行；行内空格不拆元素。能处理最后一行没有换行符的文本。

### while read：逐条处理

```bash
while IFS= read -r line || [[ -n "$line" ]]; do
    printf '%s\n' "$line"
done < "$file"
```

`IFS=` 防止读取时裁掉首尾空白；`-r` 不解释反斜杠；末尾重定向为整个循环提供输入，文件打开一次。`|| [[ -n ... ]]` 保留没有末尾换行符的最后一行。

### NUL 分隔：路径包含空白也能完整读取

```bash
while IFS= read -r -d '' file; do
    rel_path="${file#./}"
    printf '<%s>\n' "$rel_path"
done < <(find . -type f -print0)
```

- `<`：给循环重定向输入。
- `<(...)`：进程替换，把命令输出提供成可读取入口。
- `-print0`：每个路径后写 NUL 字符。
- `read -d ''`：用 NUL 作为分隔符。

NUL 不是字面字符 0，也不是 NULL。空格、甚至路径内的换行都不会成为此处的记录边界。Bash 变量不能保存 NUL，这里 NUL 用作流中的分隔符，不存入变量。

### 与管道的作用域区别

```bash
count=0
printf '%s\n' a b | while read -r item; do
    ((count+=1))
done
printf '%s\n' "$count"  # Bash 默认设置下为 0

count=0
while read -r item; do
    ((count+=1))
done < <(printf '%s\n' a b)
printf '%s\n' "$count"  # 2
```

Bash 默认管道右侧循环在子 Shell 环境运行；lastpipe 等配置可能改变这一行为。进程替换版本的循环在当前 Shell，保留计数。

**限制：进程替换中 find 的失败不会自动成为 while 的失败状态。** find 只枚举部分文件时，循环可以处理已收到路径，但不能证明枚举完整。需要可靠报告完整性时，要另行检查生产者状态，例如先把结果写入临时清单并检查 find，再读取清单。

## 11. 环境、分组、进程与代码执行

### export 与临时环境

```bash
export color="blue"
color="red" bash -c 'printf "%s\n" "$color"'
printf '%s\n' "$color"
# red
# blue
```

普通变量不会自动成为外部进程环境；export 标记后供后续子进程继承，不修改系统全局配置。命令前赋值为这次外部命令提供环境，不永久改变外层变量。特殊内建等语境另有细节，本轮未展开。

内部代码使用单引号，使 `$color` 留给新 Bash 展开。

### 分组与子 Shell

```bash
count=1
( count=2 )
{ count=3; }
printf '%s\n' "$count"  # 3
```

圆括号的变量和 cd 修改通常不影响外层；大括号在当前环境执行。子 Shell 不隔离磁盘，写文件不会自动撤销。

### eval、bash -c、source

| 写法 | 作用 |
|---|---|
| `eval "$text"` | 当前 Shell 再次解析文本为代码 |
| `bash -c '代码'` | 新 Bash 进程执行代码 |
| `source ./settings.sh` | 当前 Shell 执行文件全部内容 |

```bash
cmd='echo A; echo B'
$cmd            # 普通展开，不重新把分号当语法；输出 A; echo B
eval "$cmd"     # 再次解析，分别输出 A 和 B
```

变量中保存的文本经 eval 可以成为代码。不要随意 eval 外部文本。source 会执行实际命令，不是只导入函数，不要为查看函数而 source 带安装路由入口的脚本。bash -c 的参数传递规则未作系统练习。

### 后台任务与进程编号

```bash
sleep 2 &
pid=$!
printf '%s\n' "立即继续"
wait "$pid"
printf '%s\n' "任务已结束"
```

- `&`：异步执行。
- `$!`：最近启动的后台任务进程号。
- `wait "$pid"`：等待并取得该任务状态；无参数 wait 等待当前 Shell 后台任务。
- `kill -0 PID`：不发送实际信号，用于检查进程存在及权限。
- `$$`：当前 Bash 的进程编号；Bash 的圆括号子 Shell 中保留原值，不是该子 Shell 的实际 PID。

源码 sudo 保活循环在后台反复检查主脚本并执行 `sudo -n true`。`-n` 禁止密码交互；该循环有维持认证的意图，不保证每次执行都成功。

## 12. 可靠的失败处理

### 严格选项

| 选项 | 基础作用 | 注意 |
|---|---|---|
| `set -e` | 某些未处理失败触发退出 | 条件等语境有例外，不能替代显式检查 |
| `set -u` | 展开未设置变量时出错 | 空字符串已设置，不等于未设置 |
| `set -o pipefail` | 管道有失败则返回最右侧非零状态 | 本身不让脚本退出 |

可组合 `set -euo pipefail`，但不是“开启后所有错误都自动可靠处理”。主脚本 shorinniri 没有全局开启这组选项。

`set -e` 是持续设置，不只作用下一行；`set +e` 关闭。`if` 条件、`!`、部分 &&/|| 等上下文存在例外；函数作为条件调用时，函数体内 errexit 的行为尤其不能直觉推断。本轮仅覆盖基础例子。

```bash
set -e
count=0
((count++))        # 旧值 0 → 状态 1，作为普通命令时可能在此退出
```

```bash
set -u
printf '%s\n' "${missing:-默认值}" # 可以，且不自动给 missing 赋值
```

```bash
false | true       # 默认管道状态 0
# 开启 pipefail 后，同一管道状态 1；再结合 -e 可触发退出
```

### local 可能遮蔽失败

```bash
local helper=$(get_helper)   # local 成功可能掩盖 get_helper 失败
```

推荐把声明与赋值检查分开：

```bash
local helper
if ! helper=$(get_helper); then
    printf '%s\n' "获取助手失败" >&2
    return 1
fi
```

独立赋值只有命令替换时，状态取最后一个命令替换。注意 `if ! command; then status=$?` 得到的是取反后的状态；需要原始状态时用普通 if/else：

```bash
if command; then
    :
else
    status=$?
    printf '原始失败状态=%s\n' "$status" >&2
fi
```

### 逐层传播

```bash
copy_one() { return 1; }

sync_all() {
    copy_one || return 1
    echo "同步完成"
}

sync_all || {
    echo "同步失败" >&2
    exit 2
}
echo "部署完成"
```

仅输出同步失败，脚本状态为 2。底层 return 1 不会自动结束外层；调用者必须检查。无 set -e 时，`copy_one; ((success+=1))` 会在复制失败后仍增加成功计数。

## 13. 文件描述符、排他锁与临界区

源码采用类似结构：

```bash
(
    exec 9<"$protection_dir" || exit 1
    flock -x 9 || exit 1
    manage_protection_locked "$@"
)
```

1. 子 Shell 给资源生命周期划定边界。
2. `exec 9<...` 打开目录并保留描述符 9。此处 exec 没有程序参数，只设置重定向，不替换 Shell。
3. `flock -x 9` 申请排他锁，冲突时默认等待。
4. 获锁后执行读取、修改、写回。
5. 相关打开引用全部关闭时释放锁；子 Shell 退出通常完成清理，若子进程继承引用还需考虑其生命周期。

数字 9 不是特殊锁编号；不同进程都用 9 不代表互斥，关键是锁定同一对象。flock 为协作锁，不阻止不遵守约定的程序写文件。源码锁的是目录，列表文件可用临时文件替换。

锁必须覆盖完整的**读取 → 修改 → 写回**。两进程都读 [A]，各自生成 [A,B]、[A,C]，最后写入者可能覆盖前者；只锁最后的写入不能解决这个丢失更新问题。

## 14. 可复用教学模板

以下函数是归纳模板，使用前按实际需求检查。代码包含文件写入操作，阅读笔记不会自动执行它们。

### 14.1 参数校验与普通复制

适用：普通来源文件复制；不提供备份、事务或并发保护，可能覆盖现有目标。检查与操作间仍存在竞态，不用于不可信目录中的安全边界。

```bash
copy_checked() {
    if [[ "$#" -ne 2 ]]; then
        printf '%s\n' "需要两个参数：来源和目标" >&2
        return 1
    fi

    local src="$1"
    local dest="$2"
    local dest_dir

    if [[ -z "$src" || -z "$dest" ]]; then
        printf '%s\n' "来源和目标不能为空" >&2
        return 1
    fi
    if [[ ! -f "$src" ]]; then
        printf '%s\n' "来源不是普通文件" >&2
        return 1
    fi

    dest_dir=$(dirname -- "$dest") || return 1
    mkdir -p -- "$dest_dir" || return 1
    cp -a -- "$src" "$dest" || return 1
    printf '%s\n' "复制成功"
}
```

校验顺序：数量 → 读取参数 → 空值 → 类型 → 操作。传 `""` 仍算一个参数，所以数量通过不代表内容有效。

### 14.2 调用失败时结束脚本

```bash
copy_checked "$src" "$dest" || {
    printf '%s\n' "部署失败" >&2
    exit 2
}
printf '%s\n' "部署完成"
```

在函数内希望只退出函数时用 return；最外层希望结束脚本时用 exit。

### 14.3 失败后继续处理并计数

```bash
success=0
failed=0

for file in "${files[@]}"; do
    if ! copy_checked "$template_dir/$file" "$target_dir/$file"; then
        ((failed+=1))
        continue
    fi
    ((success+=1))
done
printf '成功=%s，失败=%s\n' "$success" "$failed"
```

成功两个、失败一个时输出 `成功=2，失败=1`。计数只在相应路径递增，不能把失败尝试也算成成功。

### 14.4 临时文件写入后替换目标

学习结论：直接“备份 → 删除旧目标 → 复制新文件”时，新文件复制失败会使目标缺失，只能从备份找回。更合适的替换顺序是：**备份旧配置 → 在目标同目录准备新临时文件 → 写入成功后重命名替换目标**。

下面是新增的参考模板，用于普通配置内容替换，采用 Linux/GNU 工具；不冒充本轮已独立写完的练习。不包含备份，若需要应在替换前独立完成并检查。权限策略明确设置为 0600，不保留来源元数据；信号中断、并发写入、磁盘持久性和不可信目录需另行设计。

```bash
replace_config_content() {
    [[ "$#" -eq 2 ]] || return 1
    local src="$1" dest="$2"
    local dest_dir temp_file

    [[ -n "$src" && -n "$dest" && -f "$src" ]] || return 1
    [[ ! -d "$dest" ]] || return 1
    dest_dir=$(dirname -- "$dest") || return 1
    mkdir -p -- "$dest_dir" || return 1
    temp_file=$(mktemp -- "$dest_dir/.config-replace.XXXXXX") || return 1

    if ! cat -- "$src" > "$temp_file"; then
        rm -f -- "$temp_file"
        return 1
    fi
    if ! chmod 600 -- "$temp_file"; then
        rm -f -- "$temp_file"
        return 1
    fi
    if ! mv -fT -- "$temp_file" "$dest"; then
        rm -f -- "$temp_file"
        return 1
    fi
}
```

临时文件在目标同目录，使最终重命名保持在同一文件系统；其他读取者看到旧文件或新文件，不应看到写了一半的目标内容。这种单路径替换不等于多文件事务，也不保证断电持久化。目标为符号链接时替换的是链接本身，需按需求决定是否允许。

本轮最后一项学习结论是“失败后清理本次临时文件”；最后的 mv 失败分支练习未独立作答，现作为参考答案收录，不再挂为待答任务。

## 15. shorinniri 项目读码索引与结论

### 15.1 路径映射

```text
TEMPLATE_DIR + rel_path → 来源文件
HOME + rel_path         → 目标文件
BACKUP_DIR + rel_path   → 备份文件
```

例如 rel_path 为 `.config/kitty/kitty.conf`，备份根为 `/home/example/.cache/backup/20261024`，完整备份路径是 `/home/example/.cache/backup/20261024/.config/kitty/kitty.conf`。dirname 只提取父目录。

### 15.2 backup_and_copy

源码流程：创建目标目录；已有目标满足 `-e || -L` 时创建备份目录、复制备份、删除目标；最后复制来源。

审查结论：

- mkdir、备份 cp、删除 rm 等未逐项检查；不能因为最终有成功提示就认定中间全成功。
- 备份失败后仍可能删除旧文件；删除成功后新复制失败，目标可能缺失。
- 显式 `|| return 1` 能停止后续操作，但不会自动回滚此前修改。
- 最后一条 cp 的状态可成为函数状态；外层若忽略它，仍会继续。
- 教学中新增的检查与临时替换没有写回项目源码。

### 15.3 sync_dotfiles

```bash
while IFS= read -r -d '' file; do
    local rel_path="${file#./}"
    if [[ "$mode" == "update" ]] && is_ignored "$rel_path"; then
        ((skip_count++))
        continue
    fi
    backup_and_copy "$TEMPLATE_DIR" "$rel_path"
    ((sync_count++))
done < <(find . -type f -print0)
```

- update 才检查保护规则；init 的左条件失败，不调用 is_ignored。
- 内置 `.config/niri` 保护其子路径；目录匹配通过“规则加斜杠”避免误匹配类似名称。
- continue 跳过复制与成功计数，只增加 skip_count。
- 源码调用复制函数后没有检查状态，计数可能高于真实成功数。
- find 只列普通文件；枚举失败需单独考虑，不能由 while 状态推断。
- 原脚本未全局启用严格选项。

### 15.4 cleanup_old_backups

```bash
local backups=( $(ls -dt "$BASE_BACKUP_DIR"/* 2>/dev/null) )
```

未引用命令替换会按空白拆分，还可能进行通配展开。路径带 `My Backups` 会拆坏；后面给数组元素加引号无法恢复边界。不要靠解析 ls 文本可靠存储任意文件名。源码从下标 2 清理，意图保留排序后的前两组。

### 15.5 normalize_protected_path 与规则锁

路径规范化将家目录内输入转为相对路径，拒绝家目录本身、越界、换行等。源码 realpath 使用 `-m -s`，进行词法规范化而不解析符号链接目标，不能把它当成物理路径沙箱。规则写入使用临时文件再替换，并使用目录上的 flock 保护读改写流程。

## 16. 高频易错点清单

| 易错点 | 正确认识 |
|---|---|
| return 1 当作真 | 这是退出状态，1 是失败；算术值非零为真是另一层 |
| `helper=$(fn)` 得到 return 数字 | 它捕获 stdout，状态另外从 $? 取 |
| local 与赋值合写后检查 $? | local 可能掩盖替换命令的失败，分开声明和检查 |
| return 自动结束所有外层 | 只结束当前函数，调用者需逐层处理 |
| 循环一次拿到 x y z | 每轮一个值，先执行完该轮再进入下一轮 |
| break 撤销之前输出 | 不撤销，之前输出仍保留 |
| continue 等同 break | continue 只跳本轮，下一轮仍执行 |
| `failed++` 单独写 | 用 `((failed+=1))` 等算术语法 |
| `count++` 总返回成功 | 从 0 开始表达式值为 0，状态为 1 |
| `${text:2:3}` 取到下标 3 | 第三项是长度，这里从下标 2 取 3 个字符 |
| `${file#./}` 按空格截断 | 只删除开头匹配的 ./，剩余空格保留 |
| 双引号能防止参数被当选项 | 引号保护参数边界，-- 才终止选项解析 |
| 输出自动缩写 ~ | 实际输出使用展开后的 HOME 完整路径 |
| 忽略 printf 的尖括号、冒号、等号 | 格式串里的字面字符都会输出 |
| 中文分号、`![[` | 使用英文分号；! 与 [[ 之间留空格 |
| 把输出到 stderr 当隐藏 | >&2 只改输出通道，不隐藏 |
| set -e 只管下一行 | 持续生效直到关闭或 Shell 结束，但有条件语境例外 |
| 计数成功等于复制成功 | 只有检查状态后计数，才能支持这个结论 |
| 进程替换保证生产者成功 | 保持循环作用域，不自动传播 find 状态 |
| 子 Shell 会回滚文件修改 | 只隔离部分进程环境，不回滚磁盘 |
