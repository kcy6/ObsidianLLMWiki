## 二、变量、引号与命令替换

### 1. 赋值与读取

```bash
name="niri"
echo "$name"
echo "${name}-config"
```

赋值时 `=` 两侧不能加空格。读取变量用 `$name` 或 `${name}`；花括号可以明确变量名边界。

```bash
echo "$name_config"     # 读取变量 name_config
echo "${name}_config"   # 读取 name，再接上 _config
```

### 2. 单引号与双引号

```bash
name="niri"
echo '$name'    # 输出字面文本 $name
echo "$name"    # 输出 niri
```

单引号保留原文；双引号允许变量和命令替换，并将结果保持为一个参数。路径可能包含空格，所以向命令传递路径时优先使用双引号：

```bash
path="/home/example/My Files/config.kdl"
dirname "$path"
```

易错点：引号一般是 Shell 的语法，不是赋值结果的一部分。不能因为代码里写了 `name="niri"`，就认为变量内容包含两个双引号。

### 3. 命令替换 `$(...)`

```bash
dest_dir="$(dirname "$dest_file")"
```

执行括号里的命令，将其标准输出作为替换结果；末尾的换行符会被移除。若 `dest_file` 为 `/home/example/.config/niri/config.kdl`，结果就是 `/home/example/.config/niri`。

里面的 `"$dest_file"` 属于内部命令，外层双引号包住替换结果，可以这样嵌套。

### 4. 三种常见括号

| 写法 | 用途 |
|---|---|
| `${name}` | 展开变量 |
| `$(dirname "$path")` | 获取命令的标准输出 |
| `$((count + 1))` | 计算整数表达式 |

## 三、函数、参数与退出状态

### 1. 定义与调用

```bash
show_path() {
    local base="$1"
    local file="$2"
    echo "$base/$file"
}

show_path "/home/example/My Files" "config.kdl"
```

定义函数不会立即执行。调用时写函数名和参数，不写调用括号，也不用逗号分隔参数。

| 写法 | 含义 |
|---|---|
| `$1`、`$2` | 当前上下文的第一个、第二个位置参数 |
| `"$@"` | 所有位置参数，每个参数保持独立 |
| `$#` | 位置参数数量 |
| `local name=...` | 在函数内声明局部变量 |

函数收到的位置参数与脚本本身的位置参数分开理解。

### 2. 输出与状态是两件事

```bash
check_name() {
    if [[ "$1" == "niri" ]]; then
        echo "匹配成功"
        return 0
    fi
    return 1
}
```

- `echo` 输出文本，可由 `$(...)` 捕获。
- `return 0` 表示成功，非零表示失败，不用于返回任意文本。
- 没有显式 `return` 时，函数状态取最后执行的命令的状态。
- `return` 结束函数；`exit` 结束当前 Shell。直接执行脚本时，通常就是结束脚本。

可以直接用函数作条件：

```bash
if check_name "niri"; then
    echo "进入成功分支"
fi
```

易错点：Bash 判断成功使用状态 `0`，不要套用某些编程语言里“0 为假”的直觉。文本输出内容与成功失败没有必然关系。

## 四、条件判断

### 1. `if` 的结构

```bash
if 条件命令; then
    成功时执行
elif 另一个条件命令; then
    成功时执行
else
    都失败时执行
fi
```

`if` 根据命令退出状态选择分支。`[[ ... ]]` 是 Bash 的条件判断结构，内侧需要空格。

### 2. 字符串与整数

```bash
[[ "$mode" == "update" ]]  # 字符串相等
[[ "$mode" != "init" ]]    # 字符串不相等
[[ -z "$path" ]]           # 字符串为空
[[ -n "$path" ]]           # 字符串非空
```

| 整数运算符 | 含义 |
|---|---|
| `-eq` | 等于 |
| `-ne` | 不等于 |
| `-gt` | 大于 |
| `-lt` | 小于 |
| `-ge` | 大于等于 |
| `-le` | 小于等于 |

```bash
[[ "02" == "2" ]]   # 失败：文本不同
[[ "02" -eq "2" ]]  # 成功：这里的整数值相同
```

补充易错点：Bash 的算术语境可能把前导 `0` 的常量按八进制解释，不要把任意零开头字符串都当成十进制数字。

### 3. 文件判断

| 写法 | 含义 |
|---|---|
| `-e "$path"` | 路径存在；悬空符号链接不满足 |
| `-f "$path"` | 是普通文件 |
| `-d "$path"` | 是目录 |
| `-L "$path"` | 是符号链接，包括悬空符号链接 |
| `-r "$path"` | 当前用户可读 |
| `-w "$path"` | 当前用户可写 |
| `-x "$path"` | 文件可执行；对目录表示可搜索、遍历 |

原脚本：

```bash
if [[ -e "$dest_file" || -L "$dest_file" ]]; then
    # 备份已有目标
fi
```

加上 `-L`，可以识别链接目标已经不存在的符号链接。

### 4. 组合条件

```bash
[[ -n "$path" && -f "$path" ]]  # 并且
[[ -e "$path" || -L "$path" ]]  # 或者
[[ ! -e "$path" ]]             # 取反
```

### 5. 已完成练习

假设 `path` 指向不存在的路径：

```bash
mode="update"

if [[ "$mode" == "update" && -f "$path" ]]; then
    echo "A"
elif [[ ! -e "$path" ]]; then
    echo "B"
else
    echo "C"
fi
```

我的回答：打印 `B`。正确：第一个条件因 `-f` 失败，第二个条件成立。

## 五、命令之间的 `&&`、`||` 与分组

```bash
命令A && 命令B   # A 成功才执行 B
命令A || 命令B   # A 失败才执行 B
```

原脚本：

```bash
cd "$TEMPLATE_DIR" || exit 1
```

进入目录失败就退出，防止继续在错误目录下操作。

多条处理命令可以组成一组：

```bash
sudo -v || {
    echo "认证失败"
    exit 1
}
```

`{ ...; }` 在当前 Shell 环境中执行这一组命令；这里仅在前一条命令失败时执行。换行可承担命令分隔作用；单行分组则要注意结束命令的分号以及大括号周围空白。

```bash
某个命令 || true
```

`true` 始终返回成功，使整组命令最后返回成功。这种写法容忍前一条命令失败，不会修复那个操作。

### 易错点：不要把 `A && B || C` 当作完整的 if/else

```bash
prepare && copy_file || report_error
```

如果 prepare 成功而 copy_file 失败，report_error 仍会执行。`&&` 与 `||` 在命令列表中同优先级，按从左到右结合。

我的判断：`report_error` 执行。正确，完整执行顺序是：

```text
prepare 成功 → copy_file 执行但失败 → report_error 执行
```

## 六、数组与循环

### 1. 数组基础

```bash
packages=("kitty" "waybar" "niri")
echo "${packages[0]}"    # kitty，下标从 0 开始
echo "${#packages[@]}"  # 3，元素数量
packages+=("mako")      # 追加元素
```

数组元素用空白分隔，不写逗号。`"${packages[@]}"` 将每个元素分别展开为一个参数，保留元素内部的空格。

### 2. 遍历

```bash

    fi
done
```

逐个检查包，把未安装的包加入 `to_install` 数组。

- `continue`：跳过本轮剩余内容，进入下一轮。
- `break`：退出当前这一层循环。

## 七、case 与脚本/函数参数

脚本末尾用 case 分派子命令。简化示例：

```bash
case "$1" in
    init)
        ask_for_sudo
        manage_software
        ;;
    update)
        sync_dotfiles "update"
        ;;
    protect)
        manage_protection "add" "$2"
        ;;
    *)
        echo "用法错误"
        exit 1
        ;;
esac
```

- `case "$1" in`：检查第一个参数。
- `init)`：匹配该模式时执行分支。
- `;;`：结束此分支，不再继续匹配。
- `*)`：匹配任意内容，通常作为最后的默认分支。
- `esac`：结束 case。

运行：

```bash
bash shorinniri protect ".config/My App"
```

脚本中 `$1` 是 `protect`，`$2` 是 `.config/My App`。调用：

```bash
manage_protection "add" "$2"
```

函数内参数重新对应。我的回答正确：

```text
$1 = add
$2 = .config/My App
$# = 2
```

## 八、重定向与管道

### 1. 三条标准通道

| 编号 | 名称 | 交互终端中的典型默认连接 |
|---|---|---|
| 0 | 标准输入 stdin | 键盘/终端输入 |
| 1 | 标准输出 stdout | 终端 |
| 2 | 标准错误 stderr | 终端 |

```bash
命令 > file       # 标准输出写入文件，覆盖原内容
命令 >> file      # 标准输出追加到末尾
命令 < file       # 从文件读取标准输入
命令 2> file      # 标准错误写入文件
```

`/dev/null` 会丢弃写入的数据。隐藏输出不改变命令本身的退出状态。

### 2. 我的问题：第二种重定向顺序有什么效果？

我正确判断以下命令会隐藏正常输出与错误输出：

```bash
some_command >/dev/null 2>&1
```

并进一步提问：

> `some_command 2>&1 >/dev/null` 解释一下这条指令执行效果。

核心规则：**重定向从左到右处理，`2>&1` 复制标准输出当时的连接，不是建立永久跟随关系。**

对于：

```bash
some_command >/dev/null 2>&1
```

执行顺序：

```text
1. stdout → /dev/null
2. stderr → stdout 此时的位置，也就是 /dev/null
结果：两种输出均隐藏
```

对于：

```bash
some_command 2>&1 >/dev/null
```

假设开始时两种输出都连接终端：

```text
1. stderr → stdout 此时的位置，也就是终端
2. stdout → /dev/null
结果：正常输出隐藏，错误输出仍显示在终端
```

“错误仍显示在终端”的结论以初始 stdout 连接终端为前提；若外层另有管道或重定向，要按实际初始连接分析。

### 3. 已完成练习

```bash
some_command >result.log 2>&1
```

我的回答：`result.log`。

正确：正常输出与错误输出都进入 result.log。先打开文件作为标准输出，再复制到标准错误。

### 4. 管道

```bash
locale -a | grep -iq "zh_CN.utf8"
```

`|` 把左侧命令的标准输出交给右侧命令的标准输入。这里左侧列出语言环境，右侧检查是否匹配：

- `grep -i`：忽略大小写。
- `grep -q`：不输出匹配文本，用退出状态表示是否找到。

普通 `|` 不自动转交标准错误。Bash 默认以最后一条命令的状态作为管道状态；`pipefail` 尚未正式学习。

## 九、文件读取（已讲解并继续巩固）

### 1. mapfile：整份文件读入数组

原脚本：

```bash
mapfile -t user_rules < "$USER_IGNORE_FILE"
```

每行成为一个数组元素，`-t` 去掉读取分隔符，默认是行末换行符。

若文件内容是：

```text
.config/niri
.config/My App
.config/waybar
```

效果相当于：

```bash
user_rules=(
    ".config/niri"
    ".config/My App"
    ".config/waybar"
)
```

### 2. while read：逐行处理

```bash
while IFS= read -r line; do
    printf '%s\n' "$line"
done < "$file"
```

- `read`：读取一行，保存到 line。
- `IFS=`：本次读取不裁掉行首、行尾的空白。
- `-r`：保留反斜杠，不把它当作转义符。
- `done < "$file"`：将文件作为整个循环的标准输入。
- `printf '%s\n' "$line"`：用固定格式输出字符串并换行。`%s` 放入字符串，`\n` 输出换行。

简单写法可能漏掉没有末尾换行符的最后一行。可写成：

```bash
while IFS= read -r line || [[ -n "$line" ]]; do
    printf '%s\n' "$line"
done < "$file"
```

read 即使读到了末尾部分文本，也可能因没读到完整分隔符而返回失败；右侧非空判断让这部分仍得到处理。

## 十二、后续学习补充记录

### 1. 我的问题：while read 的用法没看懂

```bash
while IFS= read -r line; do
    printf '%s\n' "$line"
done < "$file"
```

整体含义：从文件中读取一行到 line；只要读取成功，就打印该行，再读取下一行。

虽然 `< "$file"` 写在循环结尾，但它为整个循环提供标准输入。文件打开一次，读取位置不断向后移动。read 每次读取下一行，而不是重新从文件头开始。

```text
读到 kitty    → line="kitty"    → 打印
读到 My Files → line="My Files" → 打印
读到 niri     → line="niri"     → 打印
读取结束      → 循环结束
```

`line` 是自选变量名，不是关键字；`IFS=` 保留行首行尾空白，`-r` 保留反斜杠。

我的追问：删掉末尾的 `< "$file"` 后，在终端运行会怎样？

答：如果没有其他输入重定向或管道，read 从终端等待键盘输入；输入一行按回车，循环打印该行，再等待下一行。终端通常也会回显键入内容，所以可能看起来显示两次。在空行处按 Ctrl+D 可结束输入。一般规律是：read 从标准输入读取，标准输入的来源由运行环境决定。

### 2. 我的问题：不是 #@ 表示元素数吗？

应根据完整语法区分，`#@` 本身不是统计元素数的独立语法：

| 写法 | 含义 |
|---|---|
| `$#` | 脚本或函数的位置参数数量 |
| `"${items[@]}"` | 数组所有元素，每个元素保持独立 |
| `${#items[@]}` | 数组元素数量 |
| `${#name}` | 字符串长度 |

```bash
items=("a b" "c")
```

我的回答：有 2 个元素，`$#` 与 `${#items[@]}` 不一定相等。正确，两者统计不同对象。

### 3. 我的问题：管道 | 有什么作用？

```bash
printf 'kitty\nwaybar\n' |
while IFS= read -r line; do
    printf '组件：%s\n' "$line"
done
```

左边产生文本，管道将它交给右边的标准输入，read 逐行读取。输出：

```text
组件：kitty
组件：waybar
```

三种输入来源对照：

```bash
read -r line                      # 在普通交互终端中默认读取键盘输入
read -r line < "$file"            # 读取文件
printf 'hello\n' | read -r line    # 读取左侧命令的标准输出
```

最后一种仅用于说明数据来源。Bash 管道中的 read 通常运行于子 Shell，变量结果通常不会保留到外层；具体例外与 lastpipe 等设置有关，留待子 Shell 一节学习。

### 4. 进程替换与 NUL 分隔

```bash
while IFS= read -r -d '' file; do
    printf '%s\n' "$file"
done < <(find . -type f -print0)
```

- 第一个 `<` 是输入重定向。
- `<(...)` 是进程替换，运行其中的命令，将其输出提供为可读取的文件入口。
- `find . -type f -print0` 每个路径后输出一个 NUL 字节。
- `read -r -d '' file` 以 NUL 为分隔符读取。

文件名可以包含空格甚至换行符，但不能包含 NUL。因此用 NUL 分隔路径比按换行符分隔可靠。NUL 指零值字节，不是字面字符 `0`，也不同于某些语言中的 NULL。

练习中给出 `./My Files/config.ini` 与 `./notes.txt`。我的回答：“不会，空格和 NULL 不同。”判断正确，术语应写 NUL。空格不是此处的读取分隔符，所以完整路径只读取一次。

### 5. 删除匹配前缀

```bash
file="./.config/niri/binds.kdl"
rel_path="${file#./}"
dest_file="$HOME/$rel_path"
```

`${变量#模式}` 删除开头匹配的最短前缀；不匹配则保持原样。这里删除开头的 `./`。

假设 HOME 为 `/home/example`，我的路径推导正确，规范写出的实际值为：

```text
rel_path  = .config/niri/binds.kdl
dest_file = /home/example/.config/niri/binds.kdl
```

易错点：聊天中用于标记代码的反引号，以及误输入的行尾反斜杠，都不属于实际路径。

再区分 # 的位置：`$#` 为位置参数数量，`${#file}` 为字符串长度，`${file#./}` 为前缀删除。

### 6. 字符串截取

```bash
"${input:2}"     # 从下标 2 截取到末尾
"${input:2:3}"   # 从下标 2 开始取 3 个字符
```

下标从 0 开始，第三项是长度，不是结束下标。

练习：`input="abcdef"`。

- 我的回答：`a="${input:2}"` 得 cdef，正确。
- 我的回答：`b="${input:2:3}"` 得 cd；已纠正为 **cde**。
- 巩固练习：`input="waybar"`，`${input:1:3}`；我答 **ayb**，正确。

原脚本先确认字面前缀，再固定截取：

```bash
case "$input" in
    "~/"*)
        expanded_path="$HOME/${input:2}"
        ;;
esac
```

`${input:2}` 不检查前两个字符是什么；前缀删除则会检查匹配。若想删除字面的 `~/`，可使用 `${input#\~/}`，避免未引用波浪线带来的展开歧义。

### 7. 默认值展开

```bash
"${target:-默认值}"
```

target 未设置或为空时使用默认值，否则使用原值；**不修改 target 本身**。`:=` 则还会赋值，仅作为区别提示，尚未深入练习。

```bash
name=""
echo "${name:-waybar}"
echo "当前值：[$name]"
name="kitty"
echo "${name:-waybar}"
```

我的回答总体正确，但漏了第二行的方括号。实际输出：

```text
waybar
当前值：[]
kitty
```

原脚本的嵌套写法：

```bash
"${target:-$(_t "(empty)" "(空)")}"
```

target 有值则显示它，否则调用 _t 获取提示文本。

### 8. 通配模式与引号

```bash
[[ "$target_path" == "$ignore_rule/"* ]]
```

在 `[[ ... == ... ]]` 右侧，未被引用的 `*` 参与通配匹配，表示任意长度内容，包括零个字符。引用部分按字面匹配。

```bash
[[ "$path" == "$prefix/"* ]]  # 星号参与匹配
[[ "$path" == "$prefix/*" ]]  # 星号被引用，按字面匹配
```

练习条件：path 为 `.config/waybar/style.css`，prefix 为 `.config/waybar`。我的回答：“A 成立，B 不成立。”正确。

前缀加斜杠还能避免将 `.config/niri-backup/a` 当成 `.config/niri` 目录内路径。此处的模式匹配不要与命令参数中的文件名展开混淆。

### 9. 正则表达式

原脚本：

```bash
if [[ ! "$confirm" =~ ^[Yy]$ ]]; then
    return
fi
```

- `=~` 右侧使用正则表达式。
- `^` 匹配开头，`$` 匹配结尾。
- `[Yy]` 匹配一个 Y 或 y。
- `!` 取反。

因此输入必须恰好是单个 Y 或 y，否则返回。

```bash
[[ "$name" == *.kdl ]]   # 通配模式
[[ "$name" =~ \.kdl$ ]]  # 正则，匹配末尾的字面 .kdl
```

正则中 `.` 表示任意单个字符，`\.` 才是字面点；`*` 表示前一部分重复零次或多次，与通配模式中的含义不同。

最后一题：confirm 为 yes 时，A、B 哪个成立？

```bash
[[ "$confirm" =~ [Yy] ]]    # A
[[ "$confirm" =~ ^[Yy]$ ]]  # B
```

此题未由学习者独立回答，助手在进度说明时解释：**A 成立，B 不成立**。A 可匹配 yes 中的 y；B 要求整个字符串只有一个字符。建议下一轮用一道新题检查理解。
