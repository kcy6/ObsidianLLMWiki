# Codex 会话如何持续补充 Arch Linux Wiki

## 目标与当前范围

用户在 2026-10-21 提出：将 `/home/y/Documents/ChatGPT/archlinux环境搭建` 工作区的后续所有会话作为知识补充，提炼每个大问题的解决经验，包含手动配置、脚本配置和后续维护。本页保存讨论草案，不代表已经建立自动同步或完成会话收录。

现有审核、来源引用和检查要求沿用 [[wiki/AGENTS|Wiki 维护规则]]。以下流程为 Wiki 综合建议，尚待试用；用户需求来自本次对话，未导出为本地来源文件。

## 收录边界

- 所有目标工作区会话都进入来源清单，包括归档会话；删除或不可访问的记录说明缺口，不宣称全量覆盖。
- 按会话 ID 去重，标题仅供展示；记录归属工作区及发现时间。列表有数量限制时，不以一次列表返回作为完整性证明。
- 全部会话参与筛选，不要求每个会话新建一页。可复用结论并入已有主题；无关内容记录不收录理由；失败会话保留有价值的排错证据。
- 进行中的会话允许部分处理，明确已读范围与截止位置；后续追加内容需要复查受影响结论。
- 来源读取与系统操作分开：整理知识不等于执行安装、修改主机配置或运行配置脚本。

## 一篇配置指南的内容约定

| 部分 | 必须回答的问题 |
| --- | --- |
| 目标和环境 | 解决什么问题？发行版、版本、设备和前置条件是什么？ |
| 最终方案 | 实际选了什么？为什么选？有哪些限制和替代方案？ |
| 手动配置 | 依赖、命令顺序、配置路径、修改内容、逐步检查和恢复方式是什么？ |
| 脚本配置 | 脚本在哪？输入参数、作用范围、运行步骤和预期结果是什么？ |
| 验收 | 什么证据说明成功？哪些仅讨论、尚未执行或验证？ |
| 维护 | 如何更新、重新应用、迁移、排错、卸载和回退？ |
| 来源 | 依据哪些会话片段、文件版本和官方资料？ |

手动流程与脚本流程应达到同一个明确的目标状态。脚本入口链接到唯一受维护的文件，避免在多篇文章复制完整脚本。脚本尚不存在时明确写待实现；脚本只通过语法检查时不能写成目标机实测成功。

脚本设计应说明重复执行行为、已有配置冲突处理、备份位置、失败后的状态和恢复步骤；机器名称、用户名、设备标识及路径尽量参数化。密钥、令牌、代理订阅等敏感内容不得写入 Wiki 或提交到 Git。

## 证据与冲突处理

区分会话中的建议、实际执行记录、用户反馈与可核验结果。不能从一条建议命令推断已经执行，也不能从助手声称完成推断功能已经验证。

同主题新旧方案发生冲突时，先比较设备、版本、时间与采用条件。已有页面只在证据支持时更新最终方案，旧方案保留适用条件或弃用原因；证据不足则列为待验证。文献核对与本机实践分别记录。

## 来源台账与增量维护建议

每个会话记录：ID、原始标题、工作区、来源访问方式、读取时间、已读范围、内容指纹或版本、处理状态、关联页面及下一步。稳定的本地脱敏导出有利于追溯；导出位置、格式和更新策略尚未确定，不先改写来源目录。

每轮维护按以下顺序进行：

1. 枚举可访问会话并核对归档范围，与上轮清单比较；记录无法覆盖的范围。
2. 阅读新增或变化内容，区分最终方案、试验和未解决问题；来源无法固定版本时说明限制。
3. 检索现有主题及指南，合并知识，更新依赖页面和待验证问题。
4. 同步 [[wiki/index|首页]]、[[wiki/sources|来源台账]] 与 [[wiki/log|维护日志]]；只记录实际完成的范围。
5. 运行仓库结构检查，并按新增脚本的作用范围进行必要验证。结构通过不等于配置已实测。

首次可用一篇配置会话试行，随后覆盖历史会话；日后按新增内容增量处理。触发方式可选用户要求时同步、会话结束时交接或定期检查。本页不创建定时任务，不假定其他会话会自动通知本会话。

由此补充以下收录规则：

- **记录最终需求及实际状态**：临时绕过方案、用户希望采用的目标方案、尚未实施的修复分别写清楚。服务正常不等于用户已确认 Add 恢复。
- **按问题类型调整结构**：配置类突出手动部署与脚本部署；排错类突出症状、复现条件、证据、排除项、绕过办法、根因修复和回归验收。比较或选型类保留选择标准及尚未实施项。
- **脚本栏目保留适用性说明**：无配置操作时写“不适用”；尚未形成脚本时写“待实现”；诊断脚本与修改配置的脚本分别说明作用，避免为凑齐结构生成无用途脚本。
- **一段会话可以生成多个关联页面**：门户概念、故障分析与配置指南可以分开，但共用来源和问题状态；不能依据最初标题忽略后续真正解决的问题。
- **只读分析要求延续到执行边界**：知识整理可提炼分析和待实践方案，不能顺便执行源会话明确尚未要求实施的系统修复。
- **截断与脱敏属于证据缺口**：台账记录哪些命令输出未完整读取；被自动脱敏的配置值不能猜测还原，也不能直接复制成可执行示例。

建议问题状态至少区分：已定位、已有绕过办法、根因修复待实施、用户验收待确认。它们记录在正文，不新增现有检查器未支持的 YAML 状态。
