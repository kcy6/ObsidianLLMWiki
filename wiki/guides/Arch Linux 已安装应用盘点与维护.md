# Arch Linux 已安装应用盘点与维护

## 快速使用

查应用清单、安装原因和入口故障；历史总数不代表实时状态。

```bash
pacman -Qi 包名
pacman -Qo /usr/bin/程序
```

执行范围：只读查询；将包名和程序路径替换为实际值。

复用要点：保留显式/依赖原因、包外工具、配置路径和迁移选择；不将全包表直接作为必装列表。

操作细节：[[wiki/guides/Arch Linux 已安装应用盘点与维护#持续维护流程]]。

## 当前基线

[2026-10-22 本机应用分类清单](../../sources/host-inventory/2026-10-22-本机应用分类清单.md)是来源文件的原样快照。记录 1062 个 pacman 包（146 显式、916 依赖）、51 个可见桌面入口（44 个包），以及无 Flatpak 应用的观察。软件包数量不等于应用数量；依赖安装项也可能是用户直接使用的工具。以上为来源记录，未重新查询本机状态。来源：[[sources/host-inventory/2026-10-22-本机应用分类清单]]。

来源声称覆盖包数据库、系统/用户应用目录、Flatpak、/opt、/usr/local/bin、用户 .local/bin 及用户目录内三层 AppImage/desktop；不保证覆盖任意可执行文件、容器或内部插件。清单中的包用途分类是整理结果，不是依赖关系或必装标记。

Rust 工具通过用户目录的 rustup 入口单列，不计入 pacman 总数。原文提到的 `用户工具补充.txt`、`全部软件包-分类.csv` 等配套文件未随本次收录，工具链组件可用性、仓库来源及采集生成过程仍待补证。参见 [[wiki/guides/Arch Linux 使用官网 rustup 配置与维护 Rust]]。

## 持续维护流程

“列出并分类已安装应用”纳入 Arch 主机维护；在用户请求盘点、迁移准备或软件栈明显变化时更新，不建立自动定时任务。

1. 记录采集日期、系统与采集范围，保留全包、显式/依赖、桌面入口、包管理器外工具四类证据；注明未覆盖内容。
2. 按用途分类，同一包的多个入口合并理解；核对总数、唯一包数、显式与依赖合计。仓库外包不能直接认定为 AUR，需记录确认依据。
3. 与上一版比较新增、移除、版本、安装原因和分类变化；对“已安装”“可启动”“功能通过”分别记证据。
4. 维护迁移选择：每项标记通用必需、按需、硬件专属或暂不迁移，并记录配置位置、依赖、安装渠道和验收项。显式安装不自动等于必需；依赖安装也不自动等于可丢弃。
5. 新采集保存带日期的来源快照和 SHA-256，不覆盖历史记录；同步台账、主题、索引和日志，运行 Wiki 检查。

本阶段是维护流程文档；未新增采集或安装脚本。来源目录中的生成脚本尚未审阅，后续先核对其输入、分类规则及可重复性，再决定复用。

## 应用入口诊断

来源为 [[sources/codex-sessions/列出并分类已安装应用-2026-10-22会话摘录]] 的 8 轮文本；底层部分输出标记截断，历史截图未查看。本节不改变原分类清单统计，也不把安装建议写成当前包状态。

| 现象 | 来源结论与执行范围 | 后续处理 |
| --- | --- | --- |
| Yazi 从 Fuzzel 无法打开 | 报告已设置 `terminal=kitty -e` 并修正 xdg-terminals.list | 重开启动器验收，终端 desktop ID 与 shell 命令分开 |
| GParted 无窗口 | 报告已提权但缺 xorg-xhost，尚未安装修复 | 先核对启动脚本/日志，再按需完整升级安装该依赖；不全局执行 xhost + |
| 天气约 66° 与实际十几度不符 | 来源解释为华氏单位并报告已改摄氏 | 66°F 约18.9°C，不是传感器高温；截图本轮未独立复核 |
| xgps / xgpsspeed 无数据 | gpsd 未运行，连接2947被拒绝，无常见接收器证据 | 无实际 GPS 需求时不为“可打开”强行启动服务 |
| qv4l2 / qvidcap 无窗口 | 前者缺 Qt6兼容库；后者设备被已有实例占用 | 核对 `qt6-5compat` 及占用进程；关闭正确实例后再试，不自动杀进程 |

`pacman -Qi 包名`、`pacman -Qo /usr/bin/程序` 与 `/var/log/pacman.log` 分别提供当前包属性、文件归属与历史事务。日志是 pacman 收到的调用，不等于用户原始 shell 命令，也不能直接引用历史行号在新日志中定位。

Fuzzel 菜单隐藏与卸载包是不同决策。gpsd、v4l-utils 可能是其他应用依赖，不应为了移除几个入口使用强制卸载。确需隐藏时先核对系统 desktop 文件名，在用户 applications 目录创建同名覆盖并加 `Hidden=true`，保留原入口记录；恢复时仅撤销自己的覆盖。来源尚未实施隐藏，无需添加通用批量隐藏脚本。

以上新增诊断尚缺目标环境的完整 GUI 验收。详情关联 [[wiki/guides/Niri 文件选择器与桌面应用入口排错]]、[[wiki/guides/Nautilus 书签与文件缓存维护]]。默认 read-only 盘点不试开摄像头、提权程序或改变单位设置。
