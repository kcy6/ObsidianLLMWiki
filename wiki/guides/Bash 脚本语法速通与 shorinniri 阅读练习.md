## 基础速查

依据完成稿第1–8节。

| 查什么 | 写法与边界 |
| --- | --- |
| 变量、引号 | `name="value"` 等号两边无空格；单引号保留原文，双引号保护普通参数边界并允许展开 |
| 变量名边界 | `${name}_config`；未引用普通参数展开可能分词并进行文件名展开，赋值与条件语境另论 |
| 选项边界 | `cat -- "$file"`：引号防分词，支持 -- 的命令用它终止选项解析 |
| 命令与算术 | `$(命令)` 捕获 stdout 并去末尾换行；`$((n+1))` 产生文本，`((n+=1))` 是算术命令 |
| 路径处理 | `${file#./}` 删除匹配最短前缀；`${input:2:3}` 从下标2取3个字符；`${target:-默认值}` 不给变量赋值 |
| 函数与参数 | `fn() { ...; }` 定义；`fn 参数` 调用；`$#` 为参数数，`"$@"` 保持各参数独立，local 声明函数局部变量 |
| 返回 | stdout 传文本，return 传状态；0成功、非零失败；`$?` 必须立即保存；return 只结束当前函数 |
| 条件与连接 | `[[ ... ]]` 内侧留空白；`A && B || C` 中 B 失败仍会执行 C；`command || true` 不修复失败 |
| 模式与正则 | `[[ "$path" == "$prefix/"* ]]` 的星号参与模式匹配；`=~ ^[Yy]$` 要求整个值恰好为Y或y |
| 数组 | `"${items[@]}"` 分别传元素；`"${items[*]}"` 按IFS首字符连接为一个参数；`${#items[@]}` 为元素数 |
| 循环 | 每轮执行完整循环体；continue 跳过本轮，break 退出当前循环，均不撤销此前操作 |
| 递增 | `((count++))` 从0开始时状态为1；前置递增也不能保证任意值都返回成功 |

## 重定向与文件读取

依据完成稿第9–10节。重定向从左到右处理，`2>&1` 复制 stdout 当时的连接，不是永久跟随。

| 写法 | 结果 |
| --- | --- |
| `command >result.log 2>&1` | 两种输出进入文件，覆盖旧内容 |
| `command >/dev/null 2>&1` | 两种输出丢弃，不改变命令自身状态 |
| `command 2>&1 >/dev/null` | stderr保留原stdout连接；只有原连接为终端时才说错误仍显示在终端 |
| `printf '%s\n' "$text"` | 固定格式输出，内容不当作格式串解释 |
| `mapfile -t items < "$file"` | 按行读数组，行内空格不拆元素 |
| `IFS='/' read -r -a parts <<< "$path"` | here-string补换行，按斜杠读入数组 |
| `cat << 'EOF'` | 引用结束标记禁止正文变量/命令/算术展开，结束行仍写EOF |

保留无末尾换行的最后一行：

```bash
while IFS= read -r line || [[ -n "$line" ]]; do
    printf '%s\n' "$line"
done < "$file"
```

任意普通文件名用 NUL 分隔；路径可能包含换行，不能仅按换行拆分：

```bash
while IFS= read -r -d '' file; do
    printf '<%s>\n' "${file#./}"
done < <(find . -type f -print0)
```

循环在当前Shell，区别于默认管道右侧子Shell中的循环。但 **find 的失败不会自动成为 while 的失败状态**；完整性要求高时需另查生产者状态，例如先写临时清单并检查find，再读取。NUL用作流分隔符，不能保存在Bash变量中。

## 环境与进程

依据完成稿第11节。

| 写法 | 作用与限制 |
| --- | --- |
| `export name=value` | 供之后子进程继承，不修改系统全局配置 |
| `name=value 外部命令` | 该次外部命令环境；特殊内建等语境另论 |
| `( commands )` | 子Shell环境，变量/cd通常不影响外层，磁盘写入不会回滚 |
| `{ commands; }` | 在当前环境执行分组 |
| `source 文件` | 当前Shell执行文件全部内容，不是只导入函数 |
| `eval "$text"` | 当前Shell再次把文本解析成代码；不随意解释外部输入 |
| `bash -c '代码'` | 新Bash执行；参数传递规则适合以后按需复查 |
| `任务 &`、`$!`、`wait "$pid"` | 后台运行、记录最近后台PID、等待并取得其状态 |
| `kill -0 PID` | 检查存在性及权限，不发送实际信号 |
| `$$` | 圆括号子Shell中仍保留原Bash值，不是子Shell实际PID |

## 失败处理

依据完成稿第4、8、12节。

- 命令状态0表示成功；算术表达式值0是假，`((0))` 因而返回状态1。两层含义分开。
- set -e 的条件、!、逻辑列表及函数调用上下文有例外，不能替代显式检查；set -u 区分未设置与空值；pipefail返回管道最右侧非零状态，本身不负责退出。
- `local helper=$(fn)` 可能让local成功掩盖fn失败；先声明，再独立赋值并检查。
- `if ! command; then status=$?` 得到取反后状态；要保留原值用普通if/else，在else中立即保存。

```bash
local helper
if helper=$(get_helper); then
    :
else
    status=$?
    printf '获取失败，状态=%s\n' "$status" >&2
    return "$status"
fi
```

上例放在函数体中，get_helper需由调用方定义。失败须逐层传播：复制函数失败 → 同步函数检查并return → 最外层检查并exit。只有成功分支才增加成功计数；停止后续操作不等于回滚此前修改。

## 文件描述符与锁

依据完成稿第13节：`exec 9<"$dir"` 只打开并保留描述符，未指定程序时不替换Shell；`flock -x 9` 对该打开对象申请排他锁。各进程都用数字9不代表互斥，必须约定锁同一对象。

临界区覆盖**读取→修改→写回**，只锁最后写入仍可能丢失更新。flock为协作锁，不阻止其他程序绕过约定。子Shell退出通常关闭引用，继承引用的子进程可能延长锁生命周期；复杂并发仍需单独设计。

## 项目读码结论

依据完成稿第15节；这是学习笔记对其源码基线的审查，未重新审计后续版本。

- TEMPLATE_DIR、HOME、BACKUP_DIR分别拼接同一rel_path，得到来源、目标、备份路径。
- backup_and_copy的mkdir、备份、删除等未逐项检查；失败后可能继续删除或留下缺失目标。
- sync_dotfiles仅update检查保护；未检查复制状态就增加计数，成功数可能失真。
- `local backups=( $(ls ...) )` 丢失参数边界，之后再引用数组元素不能修复；不靠解析ls可靠传递任意文件名。
- realpath -m -s为词法规范化，不能作物理路径沙箱；规则更新用目录锁覆盖读改写。

教学检查与临时替换**没有写回项目源码**。配置迁移的条件、保护机制和其他课程见 [[wiki/guides/shorin-niri 源码学习与配置迁移路线]]。
