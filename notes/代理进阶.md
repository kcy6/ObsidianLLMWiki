

# 代理模式篇

## 1.将数据交给本地http/socks服务的系统代理

平时使用的基于clash，v2ray，xray等的内核代理客户端都支持这种方式，但不是所有软件都支持系统代理，除开浏览器绝大部分软件连设置系统代理的地方都没有。并且系统代理一般都是http代理不是socks代理，而HTTP代理不支持udp，所以一般使用系统代理都是看看网页聊聊天

## 2.使用虚拟网卡接管系统全局流量的tun/tap代理(重点)

这种模式的原理是创建一张虚拟网卡，从网络层接管电脑的所有流量，因为所有发往互联网的流量都必须经过网络层的封装，手机默认就是这种模式所以才能实现所有app翻墙，clash在开启tun模式后会创建一张虚拟网卡接管所有流量，如果开启了tap则可以还可以向下封装MAC，推荐使用tun模式，当clash通过虚拟网卡接管并进行后续加密后在将流量发往物理网卡。接收时也是要先通过clash。

`部分非常严格的程序，网站，游戏可能会检测到电脑开启了虚拟网卡代理为了将代理过程对电脑完全透明，可以将clash的虚拟网卡转移到路由器中即软路由,可以使用虚拟机或闲置的安卓手机充当软路由。`

```
支持tun模式的软件有clash,sstap,netch,sing-box,v2ray不过xray不支持
```

使用的主流的翻墙协议都无法封装网络层的数据包(IP)，最明显的特征是使用ping命令这个网络层的工具，当使用了tun模式时ping会返回一个假的延迟即从虚拟网卡返回的，真正的VPN是可以代理网络层的数据如wireguard，

## 3.能封装网络层数据包的真VPN代理

 VPN即虚拟私有网络，即不需要与某台电脑接入同一个局域网就可以通信，而要实现这个功能就必须要有能够封装网络层的数据包，这样才能实现异地组网，才能实现内网穿透，才能虚拟得处于同一局域网里才能称为VPN。VPN是一种技术。

但VPN并不是适合用来翻墙是，VPN的流量会很清晰的写明这个流量就是VPN虽然内容被加密但会被防火墙重点关注。

<u>*总结*</u>

```
tun模式是目前比较完美的客户端代理方式，既能在网络层接管所有流量又能实现分流，对于平时使用网页的用户适合使用系统代理，真VPN并不适合用来翻墙而是内网穿透。
```

# DNS泄露篇

查询dns泄漏：https://ipleak.net/如果出现国内的DNS服务器则肯定泄露了，即使没有出现国内的DNS如果同一个节点使用全路模式和分流模式的检测结果不同也大概率泄露了，并且直接将DNS检测到的网站加入到分流规则中来绕过DNS泄露是一种掩耳盗铃的做法，DNS泄露会导致运营商或防火墙知道。

DNS泄露只有在使用代理的情况下才存在。在不使用代理的时候泄露的只有上游的DNS不能准确定位我们的位置，但是使用代理之后就会。DNS泄露的原因就是在开启了代理的情况下本地发送了DNS请求，如果能让本地不发送请求直接将数据加密后发送给节点服务器就能避免了，因为加密的数据中已经包含了域名，节点服务器会负责DNS并帮我们访问网站，通常本地进行DNS获取IP的行为只是为了匹配分流规则，所以只要分流规则配置合理就能避免发起DNS，然后将获取DNS的过程交给节点服务器。
